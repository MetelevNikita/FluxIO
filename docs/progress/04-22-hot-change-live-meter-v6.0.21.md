# 04.22 — Надёжный HOT CHANGE и live audio meter v6.0.21

Дата: 2026-08-14.

## Симптом

Правки LOGO и FX в следующих роликах визуально сохранялись в Playlist, но не
всегда доходили до уже работающего UDP playout. Синхронизация Current была
связана с готовностью PostgreSQL recovery/autosave, а несколько быстрых правок
могли отправляться конкурентно. Индикатор звука обновлялся раз в секунду и
выглядел оторванным от текущего ролика. Большой таймкод закрывал часть графики в
Playlist Preview.

## Реализация

1. Current Playlist синхронизируется с активной сессией независимо от recovery
   autosave. Изменение отправляется через 250 мс после последней правки.
2. HOT CHANGE-запросы поставлены в последовательную очередь. Более поздняя
   правка больше не может быть перезаписана медленным предыдущим запросом.
3. Media-service сохраняет уже сыгранную и текущую часть. Если изменился
   следующий ролик, старый prefetched video/audio renderer завершается и сразу
   создаётся новый с актуальными AGE, LOGO, FX и Burn-in SRT. Program encoder,
   TSDuck и UDP endpoint продолжают работать.
4. После успешного ответа Playlist показывает сообщение `HOT CHANGE applied`.
5. Эфирный RMS в `dBFS`, который FFmpeg измеряет после сборки PCM program,
   опрашивается через отдельный лёгкий endpoint каждые 100 мс вместо 1000 мс.
   Основной Playlist и системные метрики при этом не перерисовываются чаще.
6. Из Playlist Preview удалён большой экранный таймер. Точный таймкод остаётся
   в transport bar под монитором.

## Ограничение границы эфира

HOT CHANGE применяется только к ещё не начавшимся роликам. Уже закодированные
кадры текущего ролика не меняются. Для изменения текущего ролика используется
`Take on air`, который является отдельной операторской операцией.

## Проверка

- TypeScript typecheck web и media-server;
- штатные media-server tests;
- реальный FFmpeg/TSDuck UDP regression 1920×1080 с двумя роликами;
- во время первого ролика второму назначается новый LOGO;
- лог подтверждает `HOT CHANGE armed for clip 2`, затем оба ролика завершаются
  через один persistent encoder без остановки TSDuck.

## Проверка оператором

1. Запустить UDP эфир минимум из двух роликов.
2. Пока идёт первый, на втором включить/выключить LOGO либо добавить/удалить FX.
3. Дождаться `HOT CHANGE applied` в Playlist и
   `HOT CHANGE armed for clip 2` в Log Output.
4. На старте второго ролика проверить новую композицию в post-TSDuck Preview и
   на приёмном анализаторе.
