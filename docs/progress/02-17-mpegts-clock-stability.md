# 02.17 — Стабильная временная шкала MPEG-TS

## Симптом

Во время вещания FFmpeg мог многократно выводить:

```text
[mpegts] dts < pcr, TS is invalid
```

Рядом отображались сообщения HLS об открытии `index.m3u8.tmp` и очередных
`segment-*.ts`. Обновление временного файла плейлиста и создание сегментов —
нормальная работа live preview, а предупреждение `dts < pcr` относится к
выходному программному MPEG-TS.

## Причина

Для внутренней CBR-линии `FFmpeg -> TSDuck`, которая используется SRT и
SCTE-35, задаётся фиксированный `muxrate`. При этом MPEG-TS muxer запускался с
нулевыми `muxdelay` и `muxpreload`. У muxer не оставалось временного запаса для
правильного порядка DTS и PCR, особенно при H.265, B-frames и кратковременных
скачках битрейта.

## Исправление

- `muxdelay` установлен в `0.7` секунды;
- `muxpreload` установлен в `0.5` секунды;
- FFmpeg log level изменён с `info` на `warning`;
- прогресс вещания продолжает поступать отдельно через `-progress pipe:1`.

Буфер применяется только MPEG-TS muxer'ом. HLS preview продолжает обновляться
раз в секунду, а приложение по-прежнему показывает состояние, FPS, битрейт и
позицию плейлиста из progress-протокола FFmpeg.

## Проверка

Команда с фиксированным `muxrate` была воспроизведена локально на FFmpeg 8.1.2:
нулевой mux delay вызвал `dts < pcr`, а значения 0.7/0.5 устранили
предупреждение. В автоматических тестах зафиксированы новые mux-параметры и
уровень логирования.
