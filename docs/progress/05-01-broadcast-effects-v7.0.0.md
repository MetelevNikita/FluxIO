# 5.1. Эфирные эффекты второго уровня (v7.0.0)

## Задача

Вкладка `Effects` умела только импорт Lottie/alpha-оверлеев: оператор сам решал,
на какой ролик положить картинку и в каком окне её показать. Требовалось
добавить пять эфирных эффектов с собственным поведением — Animation in/out,
Next program, Ticker crawl, Clock / countdown и Stinger transition — и отделить
их в интерфейсе от уже существующих Lottie-эффектов.

## Модель трёх уровней

| Уровень | Что это | Цвет в UI |
|---|---|---|
| 1 | Логотип канала, возрастная плашка | зелёный |
| 2 | Пять параметрических эфирных эффектов | синий |
| 3 | Импортированный Lottie/alpha-оверлей | жёлтый |

Ключевое решение: эффект второго уровня **не рисуется напрямую**. Перед
применением он *разрешается* в те сущности, которые эфирный контур уже умеет
отдавать:

```text
эффект уровня 2  ──►  FX-слои           (graphicEffectLayerSchema)
                 ├─►  текстовые оверлеи (broadcastTextOverlaySchema)
                 └─►  звуковые вставки  (clipAudioOverlaySchema)
```

Поэтому supervisor, encoder и TSDuck про уровни ничего не знают, и вся новая
логика оказалась в чистых функциях, проверяемых тестами без запуска процессов.

## Что сделано

### Контракты

- `broadcastEffectDefinitionSchema` — вид эффекта, ссылка на пресет уровня 3 и
  набор настроек всех пяти видов; поле `broadcast` в `graphicEffectAssetSchema`.
- `broadcastTextOverlaySchema` — динамическая надпись (`static`, `ticker`,
  `clock`, `countdown`) и `broadcastTextStyleSchema` для её оформления.
- `clipAudioOverlaySchema` — звуковая вставка ролика.
- `graphicEffectLayerSchema` получил `sourceInSeconds`, `blendMode`,
  `lumaThreshold` и `tier`.
- `playoutItemSchema` и снимок рабочей области получили `textOverlays` и
  `audioOverlays`.
- `broadcastTaskFileSchema` принимает и один объект, и массив объектов.

### Media-service

- `effects/broadcast-task.ts` — разбор файлов задания и текстов бегущей строки.
- `ffmpeg/text-overlay.ts` — построение `drawtext` для строки, часов и отсчёта.
- `command-builder.ts` — смещение внутри источника, `lumakey`, текстовые
  оверлеи поверх всей графики, подмешивание звука через `amix`.
- `playout-supervisor.ts` — эфирный якорь времени и проверка звуковых вставок.
- Маршруты `POST /api/effects/broadcast/task` и `.../ticker-source`.

### Интерфейс

- `broadcast-effects.ts` — чистый планировщик всех пяти эффектов.
- `screens/BroadcastEffectInspector.tsx` — панель настроек каждого вида.
- Каталог эфирных эффектов и синие карточки в `EffectsScreen`.
- Синие чипы `L2` и дорожки надписей в `PlaylistPreviewScreen`.
- Три новых нативных диалога: файл задания, тексты строки, файл перехода.

## Три решения, которые стоит помнить

### 1. Stinger режется по стыку, а не накладывается поверх него

Эфир катится независимыми рендерерами — по процессу на ролик, — поэтому стык
роликов физически проходит по границе двух процессов. Общий оверлей поверх
обоих роликов невозможен без переписывания rolling playout на два одновременных
видеовхода.

Переход режется по `Cut point`: кадры `[0, cut)` ложатся на хвост ролика A,
кадры `[cut, duration)` — на голову ролика B из того же файла со смещением
`sourceInSeconds`. Переключение источника остаётся штатным стыком плейлиста и
происходит ровно там, где графика полностью закрывает кадр.

Что это дало: длительность расписания, PCR, mux clock, SCTE-35 cue plan и
недельная сетка не изменились вообще. Единственная правка в эфирном контуре —
`trim=start=` вместо `trim=start=0` у FX-слоя.

Альтернатива «вставить переход отдельным элементом плейлиста» отклонена: она
удлиняет расписание на длительность каждого перехода, из-за чего едет сетка и
теряет смысл сама точка `Cut point`.

### 2. Часы привязаны к эфирному времени, а не к системным

Rolling playout запускает рендерер следующего ролика заранее — тот наполняет
pipe и блокируется. Если бы часы рисовались через `%{localtime}`, первые кадры
каждого ролика показывали бы момент их генерации, то есть будущее.

Вместо этого supervisor держит якорь `#airEpochAnchor` — момент, когда ролик
реально ушёл в эфир, — и передаёт рендереру `airEpochSeconds` очередного
ролика как сумму якоря и длительностей промежуточных роликов. Надпись строится
как `%{pts:gmtime:<эпоха>:%H}`, то есть от PTS кадра, а не от часов машины.
`gmtime` со сдвигом пояса вместо `localtime` — чтобы результат не зависел от
временной зоны сервера. Длительности точные, поэтому за недельную сетку часы
не накапливают ошибку.

### 3. Звук стингера подмешивается до хвоста, фиксирующего длину

Program encoder читает по одному raw-PCM pipe на дорожку, и одна отставшая
дорожка останавливает выдачу целиком. Длину дорожки закрепляет хвост
`apad=whole_len=N,atrim=end_sample=N`.

`amix` вставлен строго между `loudnorm` и этим хвостом: `normalize=0` не даёт
приглушить основную дорожку, `duration=first` не даёт её удлинить, а число
сэмплов на выходе остаётся прежним. Вставка идёт после `loudnorm`, чтобы
нормализация не трогала авторский уровень перехода.

Дополнительно `prepareItems` пробует файл вставки через `ffprobe` и молча
выбрасывает её, если звуковой дорожки нет: иначе рендерер упал бы уже в эфире.

## Найдено при проверке

Прогон сгенерированных фильтров через настоящий FFmpeg вскрыл две вещи.

**Двоеточие нужно экранировать даже внутри кавычек.** Кавычки снимаются разбором
графа, а деление на опции `key=value` идёт уже после этого — по неэкранированным
`:`. Часы и отсчёт падали на `No option name near 'gmtime:...'`. Исправлено:
`%{pts\:gmtime\:...}` — так же, как в давно работающем `escapeDrawtext` для
возрастной плашки.

**Homebrew-формула `ffmpeg` собрана без `drawtext`** (нет libfreetype) — тот же
класс проблемы, что и libass для burn-in субтитров. Добавлен флаг
`capabilities.supports.dynamicText` и preflight-проверка: без фильтра Start
останавливается заранее с внятным текстом вместо `AVFilterGraph: No such filter`.
Эффекты без надписей — Animation in/out, Next program с пресетом, Stinger — при
этом работают.

Полностью отрендерить бегущую строку и часы на этой машине не удалось: сборки с
libfreetype нет. Проверено, что граф и опции разбираются без ошибок, а
единственная оставшаяся жалоба FFmpeg — отсутствие самого фильтра.

## Ограничения

- Пресетом может быть только уже импортированный эффект уровня 3.
- Содержимое файла задания живёт в памяти сессии; путь сохраняется, файл
  перечитывается кнопкой.
- Шрифт динамических надписей — системный по умолчанию.
- Обратный отсчёт не вызывает следующее событие.
- Бегущая строка, часы и отсчёт требуют сборки FFmpeg с libfreetype.

Инструкция для инженера эфира — `docs/broadcast-effects-engineer-runbook.md`.
