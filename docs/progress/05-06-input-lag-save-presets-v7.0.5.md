# 5.6. Ввод, кнопка Save и пресеты во всех эффектах (v7.0.5)

## Залипание оказалось двумя разными вещами

Подсказка «именно на инпутах с текстом и селекторах» позволила воспроизвести
обе причины в браузере.

**Числовое поле схлопывалось в ноль.** `input[type=number]` отдаёт пустую строку
для любого незавершённого ввода — «1.», «-», «1e». Прямое `Number(value)`
превращало это в ноль и возвращало поле назад: набрать дробное значение или
стереть содержимое было невозможно. Замерено до правки: `1.` → `0`, пустое
поле → `0`. Теперь поле держит собственный черновик и отдаёт наружу только
законченные числа.

**Текстовые поля не откатывались, а запаздывали.** Каждое нажатие клавиши шло в
глобальную библиотеку эффектов и перерисовывало всё дерево приложения, включая
селектор системных шрифтов на 347 `option`. Правки:

- набор держится в локальном черновике, в библиотеку уходит с задержкой 300 мс;
- блок оформления, числовое и текстовое поля обёрнуты в `memo`.

Замерено после правки: 24 нажатия подряд, медиана **16.7 мс** на нажатие — это
и есть ожидание кадра, то есть работы в кадре практически нет.

## Найдено попутно: media-service был версии 6.0.22

Служба, с которой работал интерфейс, запущена двумя днями раньше и не знает
поля `broadcast`. Zod по умолчанию срезает незнакомые ключи, поэтому **при
каждом сохранении сессии настройки эфирных эффектов молча терялись**, а после
перезапуска карточки превращались в пустые «VIDEO · 0×0».

Чтобы это больше не проходило незаметно, интерфейс сверяет свою версию с
версией media-service и показывает предупреждение с прямым указанием, что
именно ломается.

## Кнопка Save

Настройки эффекта правятся уже после того, как он разложен по плейлисту, и сами
разложенные слои при этом не менялись. Теперь в заголовке инспектора есть `Save`
со счётчиком назначенных роликов: она пересобирает слои ровно для тех роликов,
которые эффект уже несут, сняв прежние.

Снятие и повторная раскладка идут одним проходом — состояние React обновляется
асинхронно, и раскладка по ещё не очищенному плейлисту добавила бы вторую копию
слоёв поверх старых.

Проверено: длительность 60 → 25 с, после `Save` в таймлайне `25.0 с`,
окно `00:00:00:00 – 00:00:25:00`, дублей нет.

## Пресеты во всех эффектах второго уровня

Выбор Lottie-пресета добавлен стингеру — планировщик это поддерживал давно
(`assetPath ?? preset.filePath`), не хватало контрола. Приоритет показан прямо
в интерфейсе: выбранный файл перекрывает пресет, снять файл можно кнопкой.

Кроме того, во всех пяти эффектах рядом с выбором появилась кнопка
**«Подгрузить Lottie»**: файл анализируется, попадает в библиотеку как эффект
уровня 3 и сразу назначается пресетом — без похода в общий импорт и обратно.

## Окно предпросмотра

Уменьшено до 300 px по ширине: оно показывает поведение эффекта, а не служит
мониторингом, и место в инспекторе нужнее настройкам.

## Проверка

- `npm run typecheck` — без ошибок.
- `npm test` — 147 тестов, 0 падений: 84 media-server, 41 web, 22 корневых.
- В браузере: числовое поле принимает «1.» и пустое значение; 24 нажатия с
  медианой 16.7 мс; `Save` переносит настройки без дублей; у всех пяти эффектов
  есть и выбор пресета, и кнопка подгрузки; предупреждение о версии 6.0.22
  показывается.

## Важно при обновлении

Media-service **обязательно** перезапустить обновлённой сборкой. До этого
настройки эфирных эффектов не переживут сохранение сессии — старая служба
вырезает поле при записи.
