# Восстановление Playlist-сессии

Применимо к FluxIO **v5.0.3**.

## 1. Что сохраняется

Кнопка **Save session list** в верхней панели Playlist создаёт snapshot в
локальном PostgreSQL. В него входят:

- Current и Future в текущем порядке;
- данные проанализированных материалов и выбранный ролик;
- метаданные `.air/.txt`, AGE, LOGO и SCTE-35 markers;
- настройки encoder и endpoint;
- выбранные папки AGE/LOGO.
- выбранный стартовый ролик Current Playlist.

SRT passphrase и RTMP stream key удаляются из JSON snapshot и хранятся отдельно
в AES-256-GCM виде. Для этого в `.env` должен существовать `GRUBER_SECRET_KEY`.

Изменения после последнего нажатия **Save session list** не становятся частью
snapshot автоматически. После изменения расписания сохраните сессию ещё раз.

## 2. Runtime checkpoint

После сохранения snapshot media-server каждые 5 секунд записывает:

- runtime session ID и состояние FFmpeg;
- индекс и имя текущего ролика;
- прошедшее время всего Playlist;
- общий progress и номер repeat-цикла.

Checkpoint обновляется самим media-server и не зависит от открытого Electron.
При штатной остановке сервера выполняется дополнительная финальная запись.

При внезапном отключении питания checkpoint может отставать примерно на пять
секунд. Поэтому при восстановлении возможно повторное прохождение нескольких
секунд материала. Автоматическая отправка сигнала после загрузки ОС запрещена:
решение о продолжении принимает оператор.

## 3. Восстановление после запуска

1. Запустить media-service и Electron обычным production launcher.
2. Electron автоматически запросит последний snapshot из PostgreSQL.
3. Если предыдущий playout был прерван, откроется Playlist и будет выбран
   ролик из checkpoint.
4. Перейти в **Broadcast Settings**.
5. Проверить жёлтый блок `Interrupted playout checkpoint found`.
6. Выбрать один вариант:
   - **Resume Stream** — исключить уже завершённые ролики и начать текущий ролик
     с сохранённой позиции;
   - **Start from beginning** — запустить сохранённый Current с первого ролика.

При Resume прошедшие SCTE-35 markers текущего ролика удаляются из нового запуска,
а AGE-плашка не показывается повторно. Постоянный LOGO остаётся включённым.

Recovery checkpoint имеет приоритет над ручным стартовым маркером. Поэтому
`Resume Stream` продолжает прерванный эфир, `Start from Marker` начинает с
выбранного оператором ролика, а `Start from beginning` игнорирует оба варианта.

## 4. Стартовый ролик и горячий переход

В Current Playlist у каждого ролика есть действие:

- **Start here** — назначить ролик первой позицией следующего запуска;
- **Take on air** — во время активного эфира немедленно перейти к ролику.

При горячем переходе media-server сначала проверяет новый срез плейлиста и
доступность FFmpeg/TSDuck, затем корректно останавливает текущие процессы,
дожидается освобождения endpoint и запускает новый playout. Интерфейс требует
подтверждение, чтобы исключить случайное переключение эфира.

Горячий переход является управляемым restart, поэтому в UDP/SRT/RTMP возможен
короткий разрыв сигнала и новый transport/session timeline. Это не бесшовный
frame-accurate transition. Для критичного эфира переключение нужно проверить
на резервном endpoint и согласовать допустимую длительность разрыва с ГС.

Маркер сохраняется только кнопкой **Save session list**. Он не записывается в
экспортируемый `.air/.txt` и не является SCTE-35 cue.

## 5. New playlist

Кнопка **New playlist**:

1. запрашивает подтверждение;
2. останавливает активный playout, если он ещё работает;
3. удаляет recovery snapshot и checkpoint из PostgreSQL;
4. очищает Current, Future, AGE/LOGO sources и возвращает настройки по умолчанию;
5. открывает Import & Analyze.

Операция необратима средствами интерфейса. Если расписание понадобится снова,
предварительно сохраните его как `.air` или `.txt`.

## 6. Обновление существующей установки

После получения версии 5.0.2 примените Prisma migration:

```bash
npm run db:generate
npm run db:migrate
npm run build
```

Мастер `node setup.mjs` выполняет эти действия автоматически.

## 7. Проверка инженером

1. Загрузить минимум три ролика и нажать **Save session list**.
2. Начать тестовый UDP/SRT playout.
3. Дождаться второго ролика и закрыть media-service аварийно.
4. Запустить FluxIO заново.
5. Убедиться, что восстановлен второй ролик и отображается время checkpoint.
6. Нажать **Resume Stream** и проверить сигнал на приёмнике.
7. Убедиться, что завершённые ролики не проигрываются повторно.
8. Остановить тест, назначить третий ролик через **Start here** и проверить
   `Start from Marker`.
9. Во время тестового эфира нажать **Take on air** у другого ролика, подтвердить
   переключение и проконтролировать восстановление потока на приёмнике.

Для приёмочных испытаний используйте тестовый endpoint: аварийное выключение
media-server намеренно обрывает транспортный поток.
