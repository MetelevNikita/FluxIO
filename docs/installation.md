# Установка и конфигурация

## Как запускать: от машины с интернетом до машины без него

Одна последовательность. Шаги 1–4 делаются там, где есть сеть; шаги 5–7 — на
эфирной машине.

**Комплект собирается на машине той же платформы, что и целевая.** Electron,
растеризатор сцены и весь медиастек между платформами не переносятся: комплект
для Windows собирается на Windows, для Linux — на Linux. Собрать на маке
комплект для эфирной машины с Windows нельзя, сборщик откажется.

### На машине с интернетом

**1. Собрать проект**

```bash
npm ci --include=dev
npm run build
```

Упаковкой Electron занимается сам сборщик комплекта — отдельно её запускать не
нужно. Если `npm ci` отработал без сети или с `--ignore-scripts`, бинарная часть
Electron остаётся нераспакованной (`node_modules/electron/dist` отсутствует), и
electron-builder падает с «The specified electronDist does not exist». Сборщик
это чинит сам: распаковывает рантайм из кеша, а при его отсутствии скачивает.

**2. Сложить медиастек в одну папку**

Единственный ручной шаг: FFmpeg, TSDuck, GStreamer и PostgreSQL скачиваются с
сайтов их авторов и раскладываются так (имена каталогов обязательны, внутри —
как приехало у поставщика):

```
tools/
  ffmpeg/bin/ffmpeg  ffprobe        FFmpeg с libfreetype и libass
  tsduck/bin/tsp                     TSDuck
  gstreamer/bin/gst-launch-1.0       GStreamer с плагином dvbsubenc
  gstreamer/lib/gstreamer-1.0/       его плагины
  postgres/bin/postgres  initdb  pg_ctl  psql  pg_isready
  postgres/share/                    PostgreSQL не стартует без своего share
```

Рядом с каждым инструментом можно положить файл `VERSION` — сборщик запишет её
в описание комплекта. Пустой каталог инструмента сборщик не пропустит: комплект
уехал бы «полным», а медиастека в нём нет.

**3. Собрать комплект**

```bash
npm run bundle:offline -- --tools-from ./tools --with-desktop --pack
```

**4. Забрать один файл**

В `release/` появятся `FluxIO-<версия>-<платформа>.run` (на Windows — `.zip`) и
`.sha256` рядом. На флешку копируются оба.

### На машине без интернета

**5. Проверить копию**

```bash
sha256sum -c FluxIO-9.0.0-linux-x64.run.sha256          # Linux
shasum -a 256 -c FluxIO-9.0.0-macos-arm64.run.sha256    # macOS
certutil -hashfile FluxIO-9.0.0-win-x64.zip SHA256      # Windows
```

**6. Установить**

```bash
./FluxIO-9.0.0-linux-x64.run /opt/fluxio
```

На Windows: распаковать zip проводником и запустить `install.cmd` внутри.

Мастер задаст шесть вопросов (профиль, режим, база, адрес службы, доступ,
действия), развернёт PostgreSQL, применит схему, запишет `.env`, поставит службу
и напечатает итог: адрес службы, куда установлено, где журнал.

**7. Запустить**

Рабочее место — ярлык FluxIO на рабочем столе. Сервер без монитора — открыть в
браузере адрес из итогового экрана и войти с паролем, который задали на шаге 6.

Вручную то же самое:

```bash
node /opt/fluxio/app/launch.mjs
```

### Когда выйдет новая версия

Повторить шаги 1–5, а на эфирной машине распаковать новый комплект **рядом** со
старым и перенести:

```bash
./install.sh --update /opt/fluxio
```

База, `.env` и настройки останутся; заменится только то, что изменилось.

## Требования

Обязательны:

- Node.js и npm версии, совместимые с `package-lock.json`;
- PostgreSQL;
- FFmpeg и ffprobe;
- TSDuck (`tsp`) для UDP/SRT transport;
- права чтения media/graphics/font файлов и записи runtime-каталогов.

Для режима DVB subtitles дополнительно нужен GStreamer с `dvbsubenc`. Electron
устанавливается как npm dev dependency и должен присутствовать даже в
production-сборке.

## Установка мастером

```bash
npm run setup
```

Флаги:

| Флаг | Назначение |
|---|---|
| `--offline` | не обращаться в сеть; зависимости и Electron уже должны находиться локально |
| `--no-start` | подготовить установку, но не запускать приложение |
| `--skip-gstreamer-check` | пропустить долгий probe `dvbsubenc`; DVB нельзя считать проверенным |

Мастер сначала спрашивает online/offline, затем режим:

- **Test / development** — dev server, Vite и Electron в режиме разработки;
- **Production** — миграции, production build, опциональный installer,
  background service и shortcut.

Повторный запуск безопасен: `.env` обновляется с двумя резервными копиями,
миграции Prisma применяются повторно, service definition заменяется актуальной.

## Офлайн-комплект

Для машин без интернета приложение ставится **комплектом**: собранное дерево,
рантайм Node, схема, титры и медиастек в одном каталоге. На целевой машине
ничего не собирается и никуда не ходит — ни npm, ни загрузка Electron, ни
установка пакетов через brew/apt/winget.

### Сборка (машина с интернетом, той же платформы)

```bash
npm run bundle:offline -- --tools-from /opt/fluxio-tools --with-desktop
```

| Ключ | Назначение |
|---|---|
| `--out <dir>` | куда положить комплект (по умолчанию `release/`) |
| `--tools-from <dir>` | каталог с подпапками `ffmpeg`, `tsduck`, `gstreamer`, `postgres` |
| `--without-tools` | собрать без медиастека: на целевой машине он уже установлен |
| `--with-desktop` | включить упакованное Electron-приложение из `apps/desktop/release` |
| `--profiles a,b` | профили установки: `workstation`, `server` |
| `--skip-build` | дерево уже собрано |

Комплект собирается **на машине той же платформы и архитектуры**: Electron,
растеризатор сцены и весь медиастек между платформами не переносятся. Версию
инструмента сборщик читает из файла `VERSION` рядом с ним.

### Что внутри

```
FluxIO-<версия>-<платформа>/
  manifest.json     версии, профили, контрольные суммы компонентов
  app/              дерево приложения: dist media-service и web, node_modules, setup.mjs
  runtime/node      интерпретатор — на целевой машине Node не нужен
  db/migrations/    схема
  assets/titles/    базовый набор .fto
  tools/<id>/       FFmpeg, TSDuck, GStreamer, PostgreSQL
  desktop/          упакованное Electron-приложение
```

`node_modules` в комплекте — не всё дерево, а рантайм-замыкание зависимостей
media-service: TypeScript, Vite, electron-builder и Prisma CLI нужны только
сборщику и весят больше, чем всё остальное приложение вместе взятое.

### Обновление комплекта

Новый комплект распаковывается **рядом** с установленным, а не поверх:
перезапись работающей установки на середине копирования оставила бы эфирную
машину без обеих версий. Перенос делается отдельной командой:

```bash
./install.sh --update /opt/fluxio            # Linux, macOS
install.cmd --update C:\FluxIO               # Windows
```

Что происходит:

1. проверяется целостность **нового** комплекта — битый не должен попасть в
   работающую установку ни одним файлом;
2. сверяются платформа и версии: чужая платформа и та же самая версия — отказ;
3. переносятся только компоненты с изменившимся отпечатком. Медиастек и рантайм
   Node от версии к версии не меняются, и сотни мегабайт остаются на месте;
4. работа передаётся мастеру уже обновлённой установки — он применяет новые
   миграции, переписывает `.env` из прежних значений и перезапускает службу.

Не трогается ничего из того, что оператор нажил:

- `data/` — кластер PostgreSQL и реестр плагинов GStreamer; компонентом он не
  является и в манифесте не описан;
- `app/.env` — вся настройка станции. Он лежит **внутри** компонента `app`,
  который заменяется целиком, поэтому уносится и возвращается отдельно.

### Единый файл

С ключом `--pack` сборщик кладёт рядом с каталогом комплекта один файл и его
контрольную сумму:

| Платформа | Файл | Как запускается |
|---|---|---|
| Linux, macOS | `FluxIO-<версия>-<платформа>.run` | `./FluxIO-….run [каталог установки]` — распаковывается и сам зовёт мастера |
| Windows | `FluxIO-<версия>-win-x64.zip` | распаковать проводником, запустить `install.cmd` внутри |

`.run` — это `sh`-заголовок и приклеенный к нему архив: заголовок отсчитывает
свои строки, а всё после них отдаёт `tar`. Архив создаётся системным `tar`
(на Windows 10+ это встроенный bsdtar), поэтому в сборщике нет ни одной
зависимости для упаковки, а права на исполняемые файлы медиастека переживают
перенос.

Рядом всегда лежит `.sha256` в формате `sha256sum` — оператор проверяет копию
штатной командой своей системы:

```bash
sha256sum -c FluxIO-9.0.0-linux-x64.run.sha256      # Linux
shasum -a 256 -c FluxIO-9.0.0-macos-arm64.run.sha256 # macOS
certutil -hashfile FluxIO-9.0.0-win-x64.zip SHA256   # Windows
```

Запуск в уже существующий каталог — отказ, а не перезапись: там могут быть база
и `.env` работающей установки.

Внутри распакованного комплекта лежит `install.sh` (`install.cmd` на Windows) —
им запускается мастер, когда комплект уже распакован: при обновлении или
повторной установке.

### Что не едет в комплект

Сборщик вырезает из `node_modules` то, что службе не понадобится никогда, — на
измерении это **79 МБ из 160**:

- компиляторы запросов Prisma для MySQL, SQLite, CockroachDB и SQL Server:
  FluxIO работает только с PostgreSQL, а каждый движок весит по 4.5 МБ в двух
  вариантах и двух форматах модулей;
- карты исходников: отладчик на эфирной машине никто не открывает;
- просмотрщик `pdfjs-dist/web`: служба использует только разбор документа.

Правила живут в `scripts/bundle-prune.mjs`, у каждого записана причина, и на
каждое есть тест — включая проверку, что компилятор PostgreSQL остаётся на
месте.

### Подпись

Наш единый файл — не подписываемый бинарник: `.run` это скрипт, `.zip` подписи
не несёт. Подписывать нужно то, что внутри:

- **Electron-приложение** (`desktop/`) — подписью и нотаризацией занимается
  `electron-builder` на сборочной машине, до сборки комплекта. На macOS тикет
  нотаризации обязательно **stapled**: на машине без интернета Gatekeeper не
  сможет проверить его онлайн;
- **Node, FFmpeg, TSDuck, GStreamer, PostgreSQL** приезжают подписанными своими
  поставщиками — пересобирать их подпись не нужно.

### Установка

```bash
runtime/node app/setup.mjs --bundle
```

Мастер сам находит комплект (`manifest.json` рядом с деревом), проверяет, что он
собран для этой платформы и этой версии, сверяет контрольные суммы компонентов —
и только потом задаёт первый вопрос. Дальше — обычные экраны мастера, из которых
исчезают сборочные: `npm ci`, typecheck и тесты, упаковка installer. Пути к
FFmpeg, ffprobe, `tsp` и `gst-launch-1.0` берутся из комплекта, схема
применяется SQL-файлами миграций.

Если комплект собран с `--without-tools`, мастер ищет медиастек в системе, как
при обычной установке.

### PostgreSQL из комплекта

Если в комплекте есть `tools/postgres`, мастер разворачивает **свой** кластер и
не трогает уже установленный на машине:

- данные — `<комплект>/data/postgres`, журналы — `<комплект>/data/postgres-log`;
- `initdb` с локалью `C` и кодировкой UTF-8: минимальный серверный образ может
  не иметь других локалей, а кластер по локали хоста вёл бы себя на соседней
  машине иначе;
- порт — из ответов мастера, `listen_addresses` — только петля;
- пароль суперпользователя лежит в `data/postgres/.fluxio-superuser` с правами
  `0600`: повторный запуск мастера должен уметь подключиться к уже развёрнутому
  кластеру;
- на Linux ставится отдельный unit `fluxio-postgres.service`, а unit
  media-service получает `Requires=` на него — после перезагрузки эфир поднимется
  сам, а `autoResumeOnLaunch` без базы не восстановил бы ни расписание, ни точку
  прерывания.

Каталог `data/` не входит ни в один компонент манифеста, поэтому обновление
комплекта его не трогает и проверка целостности его не считает.

Два ограничения, которые видно только на месте:

- **Глубокий путь установки.** Длина пути к Unix-сокету ограничена ядром (~103
  байта). Если каталог установки длиннее, сокет остаётся в системном каталоге
  по умолчанию — приложение ходит в базу по TCP на петлю, и на работу это не
  влияет.
- **Прерванная первая установка** оставляет каталог данных без `PG_VERSION`.
  Мастер распознаёт такие остатки и убирает их: `initdb` отказывается работать
  в непустом каталоге, а разбирать этот отказ на машине без интернета нечем.

### GStreamer из комплекта

Если в комплекте есть `tools/gstreamer`, мастер записывает в `.env` два
значения, и служба собирает из них окружение для процессов GStreamer:

| Переменная | Назначение |
|---|---|
| `GSTREAMER_ROOT` | каталог GStreamer из комплекта; пусто — работает системный |
| `GSTREAMER_REGISTRY` | файл реестра плагинов в каталоге установки |

Из `GSTREAMER_ROOT` выводятся `GST_PLUGIN_SYSTEM_PATH`, `GST_PLUGIN_SCANNER`,
`FONTCONFIG_PATH` (его требует `textrender` через pango) и путь к библиотекам —
и только те, что реально есть в дереве. `GST_PLUGIN_PATH` оператора при этом
снимается: плагины системы собраны другой сборкой и роняют процесс на первом же
элементе.

`GSTREAMER_REGISTRY` полезен и с системным GStreamer. По умолчанию реестр
кешируется в `$HOME`, куда служба под systemd писать не может
(`ProtectHome=read-only`), — и пересобирается при **каждом** старте, отнимая
минуты у первого ролика с субтитрами. Проверка `dvbsubenc` в мастере идёт в том
же окружении и строит реестр один раз, на установке: замер на сборочной машине —
5.8 с первый запуск против 88 мс последующих.

### Профиль «сервер без монитора»

Мастер спрашивает: «Открыть интерфейс оператора по сети?». Ответ «нет» — профиль
рабочего места: служба слушает петлю, интерфейс отдаёт Electron.

Ответ «да» включает две вещи: интерфейс раздаёт сама служба (`GRUBER_WEB_DIR`), а
`GRUBER_HOST` по умолчанию становится `0.0.0.0`. Оператор открывает адрес из
итогового экрана мастера в браузере.

Входа в интерфейс нет: FluxIO рассчитан на выделенную эфирную машину, которой
управляет один человек и которая не смотрит в интернет. **Порт службы в этом
профиле открыт всем, кто до него дотянулся в локальной сети** — ограничивайте
доступ сетью, а не приложением.

| Переменная | Назначение |
|---|---|
| `GRUBER_WEB_DIR` | каталог собранного интерфейса; пусто — раздаёт Electron |

## Переменные окружения

Файл `.env` лежит в корне. Минимальный шаблон — `.env.example`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DATABASE_URL` | нет | PostgreSQL connection string; без неё health = degraded |
| `GRUBER_SECRET_KEY` | нет | ключ шифрования SRT/RTMP secrets |
| `GRUBER_HOST` | `127.0.0.1` | адрес Fastify; оставляйте loopback |
| `GRUBER_PORT` | `4310` | порт media-service |
| `GRUBER_MEDIA_API_URL` | `http://127.0.0.1:4310` | URL для Electron/web/launcher |
| `FFMPEG_PATH` | `ffmpeg` | executable FFmpeg |
| `FFPROBE_PATH` | `ffprobe` | executable ffprobe |
| `TSDUCK_PATH` | `tsp` | executable TSDuck |
| `GSTREAMER_LAUNCH_PATH` | `gst-launch-1.0` | GStreamer launcher |
| `GSTREAMER_INSPECT_PATH` | рядом с launcher | probe плагинов |
| `GRUBER_PREVIEW_DIR` | temp | program HLS preview |
| `GRUBER_MEDIA_CACHE_DIR` | temp | clip preview cache |
| `GRUBER_EFFECT_CACHE_DIR` | temp | временные effect assets |
| `GRUBER_LOG_DIR` | Desktop/FluxIO logs или home fallback | каталог журналов |
| `GRUBER_WEB_DEV_URL` | `http://127.0.0.1:5173` | Vite URL для Electron dev |

Ключ:

```bash
openssl rand -base64 32
```

Не меняйте `GRUBER_SECRET_KEY` без плана: уже сохранённые зашифрованные secrets
станут нечитаемыми.

## Development

Первый запуск:

```bash
npm ci --include=dev
npm run db:generate
npm run db:migrate
```

Затем три процесса:

```bash
npm run dev:server
npm run dev:web
npm run dev:desktop
```

`dev:server` и `dev:web` сначала пересобирают contracts: остальные workspaces
потребляют `@gruber/contracts` из `dist`.

## Production

`npm run setup` умеет установить:

- Linux: systemd unit;
- macOS: LaunchAgent;
- Windows: Task Scheduler task;
- desktop shortcut на всех трёх системах.

Обычный запуск установленного приложения:

```bash
npm run launch
```

Launcher проверяет `/api/health`. Если background service уже активен, Electron
подключается к нему и не владеет его жизненным циклом. Если launcher поднял
service сам, он остановит только этот дочерний процесс при завершении.

## Обновление

Перед обновлением:

1. остановить эфир штатно;
2. сохранить workspace и экспортировать критичные расписания/профили;
3. сделать backup PostgreSQL и `.env`;
4. обновить код;
5. выполнить `npm ci --include=dev`, `npm run db:migrate`, `npm run build`;
6. перезапустить background service;
7. проверить совпадение version UI и media-service;
8. провести тест на резервном endpoint.

Мастер выполняет основные шаги автоматически, но не заменяет backup.

## Быстрая проверка

```bash
curl http://127.0.0.1:4310/api/health
curl http://127.0.0.1:4310/api/capabilities
npm run typecheck
npm test
```

Статус `degraded` означает, что HTTP и media-инструменты доступны, но операции
workspace/configurations без PostgreSQL вернут 503.
