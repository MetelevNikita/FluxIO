# Требования к продукту

## Назначение

FluxIO подготавливает локальные видеофайлы в плейлист и передаёт непрерывный телевизионный сигнал на головную станцию по UDP, SRT или RTMP.

## Основной пользователь

Технический специалист, который:

- выбирает папку с медиаматериалами;
- проверяет параметры и пригодность файлов;
- собирает эфирный плейлист;
- выбирает профиль кодирования и конечную точку;
- запускает и контролирует вещание.

## Реализованный одноканальный MVP

В первую версию входят:

- один медиасервер и один одновременный эфирный канал;
- сканирование локальной папки;
- анализ файлов через ffprobe;
- реальные FFmpeg thumbnails, clip preview и realtime program preview;
- ручная сборка плейлиста;
- H.264, H.265 или MPEG-2 Video; AAC, MP2 или AC-3;
- MPEG-TS по UDP или SRT;
- H.264/AAC в FLV по RTMP;
- нормализация файлов внутри realtime FFmpeg pipeline;
- опциональный logo overlay;
- старт и штатная остановка плейлиста;
- бесконечный repeat плейлиста до ручной остановки;
- планирование и фактическая выдача SCTE-35 Event ID/break markers в UDP/SRT MPEG-TS;
- per-clip SubRip с выбором между совместимым video burn-in и отдельным DVB bitmap subtitle PID в UDP/SRT MPEG-TS;
- отображение текущего элемента, позиции и метрик FFmpeg;
- сохранение playlist, encoder profile и endpoint в PostgreSQL;
- Electron package и systemd unit для media-service.

## Не входит в первый MVP

- одновременное формирование MPTS;
- несколько независимых каналов;
- сложная эфирная автоматизация по календарю;
- редактирование уже закодированной части текущего эфира;
- отказоустойчивый кластер из нескольких серверов.
- принудительный skip/next во время активного FFmpeg filter graph;
- rolling scheduler для очень длинных плейлистов;
- заранее подготовленные proxy-файлы;
- удалённое управление без VPN/защищённого reverse proxy.

## Ключевые требования надёжности

- закрытие интерфейса не останавливает эфир;
- FFmpeg не запускается через shell-команды;
- перед стартом выполняется preflight-проверка;
- состояние процесса и последние ошибки доступны после переподключения UI;
- первичный endpoint не скрывает ошибку доставки;
- preview не должен останавливать основной выход при отказе.
