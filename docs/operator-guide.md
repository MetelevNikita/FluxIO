# Руководство оператора

## Перед сменой

Проверьте:

- media-service показывает `ACTIVE` и версия совпадает с интерфейсом;
- PostgreSQL health = `ready`;
- media, graphics, fonts и network shares доступны сервисному пользователю;
- выбран правильный Current/Future;
- на резервном приёмнике видны видео и звук;
- PID/service metadata согласованы с головной станцией;
- свободное место есть для logs и preview cache.

Красный или жёлтый индикатор нельзя закрывать «по привычке»: сначала прочитайте
сообщение и проверьте output вне FluxIO.

## 1. Import & Analyze

Добавьте отдельные files, каталог или `.air/.txt`. Дождитесь ffprobe:

- Done/Analyzed — файл можно ставить в эфир;
- Pending/Queued — анализ не закончен;
- Error — путь, codec или права нужно исправить.

Импорт расписания создаёт Current либо Future. Проверяйте encoding,
`start on`, delay, warnings и недельное покрытие. Warning о типе
`movie/chop/clip` не блокирует работу, недоступный media file блокирует
production start.

## 2. Effects

Библиотека содержит file effects и broadcast effects второго уровня.

Для каждого broadcast effect:

1. задайте понятное имя;
2. заполните обязательные поля;
3. выберите scene или file decoration;
4. проверьте preview в реальной target layout;
5. назначьте clip, весь project или JSON task;
6. после правки существующего эффекта нажмите применение изменений к уже
   назначенным clips.

Незавершённый эффект остаётся видимым, но назначить его нельзя. Порядок
библиотеки определяет порядок наложения; не используйте сортировку по имени.

## 3. Playlist & Preview

В Current/Future можно:

- выбирать стартовый clip;
- переставлять и удалять clips;
- менять тип строки;
- включать AGE, logo и SRT;
- задавать In/Out graphic layers;
- назначать дополнительные audio tracks;
- сохранять отредактированное расписание;
- запускать composite preview.

`Ctrl/Cmd + click` набирает отдельные clips, `Shift + click` — диапазон,
`Ctrl/Cmd + A` — весь активный список. Групповое перемещение сохраняет порядок.

### Панель управления расписанием

Над списком стоит панель — всё, что делают с сеткой руками:

| Кнопка | Что делает |
|---|---|
| Отменить / Вернуть | шаг назад и вперёд по правкам расписания; те же `Ctrl+Z`, `Ctrl+Shift+Z` и `Ctrl+Y` |
| Прицел | возвращает к ролику, который идёт в эфире; без эфира — к отметке старта или выбранному |
| Поиск | прыгает к ближайшему совпадению; список **не фильтруется** — сетка времени должна оставаться целой. `Enter` — к следующему совпадению |
| Пн … Вс | переход к дню недели; свёрнутый день раскрывается сам |
| Добавить ролики | нативный выбор файлов, в конец расписания |
| ↥ / ↧ | добавить ролики перед первым или после последнего выделенного |
| Копировать / Вставить | `Ctrl+C` копирует выделенные строки, `Ctrl+V` ставит их **за** выбранной; счётчик на кнопке показывает, сколько роликов в буфере |
| Заменить клип | новый файл встаёт во **все** строки с этим роликом сразу |
| Корзина ↑ / ↓ | удаляет всё выше или ниже выбранного ролика, одним шагом истории |
| Ластик | очищает активное расписание целиком |
| Current / Future | поднимает эфир с той сетки, в которой стоит оператор |
| Развернуть / свернуть | все строки списка |

Ролики добавляются и перетаскиванием из проводника прямо в список. Файл, бро́шенный на
строку, **разрезает** расписание в этом месте: верхняя половина строки ставит его перед
ней, нижняя — после, и место показывает жёлтая черта. Сброс мимо строк ставит в конец.

Копия ролика — это отдельная строка со своими титрами, AGE и метками: правка одной копии не
трогает остальные. Замена клипа, наоборот, действует на все строки одного файла разом — когда
отбивку или заставку пересняли, менять её по одной строке значит забыть половину и выпустить
в эфир старый материал.

Один и тот же файл можно поставить в расписание сколько угодно раз — отбивки, заставки и
реклама в неделе повторяются, и каждая постановка создаёт свою строку со своими титрами и
метками.

Правая кнопка на строке открывает меню: **Reveal in Finder**, **Link file** (только у
пропавшего ролика), **Move to Future / Current** и **Delete**. Если выделено несколько
строк, перенос и удаление действуют на всё выделение.

Выбранная строка светится жёлтым — теми же по силе тонами, что зелёный у идущего ролика и
красный у пропавшего. При наборе нескольких строк активная остаётся жёлтой, добранные
подсвечиваются голубым.

День недели сворачивается стрелкой в его заголовке. Заголовок при этом остаётся на месте
и показывает, сколько в дне роликов, их хронометраж и сколько файлов не нашлось.

### Пропавшие файлы

Расписание хранит пути, а не файлы. Ролик, файла которого на диске нет, **остаётся в
сетке** — её собирал оператор, и выбрасывать строку нельзя, — но красится красным так же
заметно, как идущий ролик красится зелёным, и получает кнопку **Link file**: она открывает
проводник и подставляет другой файл, сохраняя титры, AGE, логотип, метки SCTE-35 и место
строки в расписании.

В эфир такой ролик не уходит — линия идёт мимо него, — но и старту не мешает: эфир
поднимается с остальными роликами, а файл подставляют под живым эфиром. Как только он
подставлен, ролик возвращается в эфирный список ближайшей горячей заменой, без перезапуска.

Эфирного времени такой ролик не занимает: его хронометраж — нули, всё, что стоит ниже,
выходит раньше, а неделя честно показывает недобор. Строка **Недобор / Перебор / Нет
файлов** над списком считает это отдельно: сколько времени не хватает до полного цикла,
сколько лишнего и сколько минут расписание не набирает из-за пропавших файлов.

У каждой строки есть **полка титров**: в ней лежат эффекты, назначенные на этот
clip на вкладке Effects. Пустая полка нарисована пунктиром, занятая — сплошной
рамкой со счётчиком, поэтому наличие титров читается на прокрутке. У свёрнутой
строки то же самое показывает значок `ТИТРЫ N`. Снять эффект можно крестиком на
его карточке; добавляют их только со вкладки Effects — «На один ролик», «На весь
проект» или по файлу задания.

Монитор над transport показывает либо выбранный clip, либо эфир — переключателем
**Ролик расписания / Смотреть эфир**. Эфирный монитор берёт тот же поток, что и
окно Broadcast; до старта в нём стоят цветные полосы. Под монитором — имя того,
что играет, и обратный отсчёт до конца ролика.

В эфирном режиме transport и Timeline Trimming пропадают целиком: ползунок,
IN/OUT и обрезка принадлежат ролику, а рядом с идущим эфиром читались бы как
управление эфиром. По той же причине там недоступна кнопка «Add at Playhead» у
планировщика SCTE-35 — метка ставится в позицию головки предпросмотра, а её в
этом режиме нет. Переключение на эфир останавливает локальный предпросмотр:
его считает тот же FFmpeg, что ведёт эфир.

### Start here и Take on air

Обе кнопки открывают одно окно: с какого места поднимать эфир. В нём видно имя
и хронометраж выбранного clip, поле «Место старта, с» и две кнопки —
**Старт с маркера** (с набранной секунды) и **Старт с начала**.

- **Start here** (эфир не идёт) запоминает clip и место внутри него; отметка
  переживает перезапуск приложения.
- **Take on air** (эфир идёт) делает preflight нового среза и управляемо
  перезапускает playout с выбранной точки.

Старт с середины clip снимает его AGE-плашку (её место — начало ролика) и
сдвигает графику, показы сцен и SCTE-35 метки на величину смещения.

Take не является бесшовным transition: возможен короткий разрыв transport.

### HOT CHANGE

Изменения будущих clips отправляются в media-service без перезапуска encoder.
Текущий уже кодируемый clip не меняется задним числом. После подтверждения
проверьте, что следующий clip и его graphics действительно появились на
monitor preview.

## 4. Broadcast Settings

Настройте:

- codec, resolution, frame rate, field order и hardware;
- GOP, B-frames и rate control;
- audio codec/channels/bitrate/loudness;
- UDP, SRT или RTMP(S);
- MPEG-TS service metadata, PID, PCR и bitrate;
- subtitle output;
- SCTE-35.

Импортированный encoding profile не содержит secrets. После импорта заново
введите SRT passphrase или RTMP key и проверьте local interface.

## 5. Preview и Start

До Start:

1. откройте composite preview проблемного clip;
2. проверьте aspect, interlace, logo, AGE, FX, titles и captions;
3. прослушайте все заявленные языки;
4. проверьте следующий clip и границу;
5. запустите на тестовый endpoint;
6. измерьте transport на независимом приёмнике.

После Start следите за:

- state = running;
- текущим clip и временем;
- fps/speed около реального времени;
- audio meter;
- output bitrate;
- continuity errors;
- SCTE-35/DVB status;
- logs без повторяющихся restart/error.

## 6. Current → Future и Repeat

Если Repeat выключен, после завершения Current Future становится активным
автоматически. Если Future пуст, дальнейшее поведение определяется
подготовленным playout request; не рассчитывайте на UI как на scheduler.

Repeat запускает Current заново. Стратегия SCTE-35 Event ID должна быть заранее
согласована: increment создаёт новые IDs на каждом круге, reuse повторяет IDs.

## 7. Stop

Используйте штатную кнопку Stop и дождитесь idle/completed. Только затем:

- закрывайте service;
- обновляйте приложение;
- меняйте endpoint, PID или hardware profile;
- выключайте компьютер.

Закрытие Electron window не равно Stop, если media-service работает фоном.

## 8. Save и recovery

Workspace сохраняется автоматически после изменений, но перед обновлением,
аварийным тестом или концом смены нажмите явное сохранение. Оно включает Current,
Future, effects, settings и start marker; media files не копируются.

После аварии:

1. откройте восстановленную сессию;
2. проверьте missing files;
3. сравните checkpoint clip/time;
4. выберите Resume только после проверки endpoint;
5. контролируйте первый кадр и звук на внешнем monitor.

## Чего не делать

- Не публиковать API в LAN для «удобства».
- Не менять PID во время running session.
- Не считать HLS preview доказательством корректного PCR/continuity.
- Не удалять source file после назначения.
- Не полагаться на software encoding для UHD без измеренного запаса.
- Не игнорировать version mismatch UI/service.
- Не применять JSON task с нулём совпадений: сначала исправьте match key.
