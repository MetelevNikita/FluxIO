# CLAUDE.md

Ориентир для работы с кодом FluxIO. Подробности предметной области — в `docs/architecture.md`
и runbook-ах `docs/*-engineer-runbook.md`; здесь только то, что нужно, чтобы быстро и безопасно
вносить изменения.

## Что это за приложение

Desktop playout: анализ локальных видеофайлов → сборка эфирного плейлиста → кодирование через
FFmpeg → выдача MPEG-TS на головную станцию по UDP / SRT или FLV по RTMP(S).

Ключевой архитектурный принцип: **эфирный контур отделён от интерфейса**. Долгоживущий
Node.js/Fastify media-service владеет состоянием в PostgreSQL и дочерними процессами
FFmpeg / TSDuck / GStreamer. Electron + React только шлют HTTP-команды и опрашивают статус,
поэтому закрытие окна не обрывает эфир. UI никогда не запускает FFmpeg сам.

## Раскладка репозитория

npm workspaces, `packages/*` и `apps/*`:

| Workspace | Пакет | Роль |
|---|---|---|
| `packages/contracts` | `@gruber/contracts` | Zod-схемы + выведённые типы. **Единственный источник правды** для формы данных между UI и сервером. |
| `packages/scene-renderer` | `@gruber/scene-renderer` | Отрисовка сцены. Одна функция `drawScene` на редактор и на эфир — второй реализации быть не должно. |
| `apps/media-server` | `@gruber/media-server` | Fastify API, Prisma, supervisor FFmpeg/TSDuck/GStreamer. |
| `apps/web` | `@gruber/web` | React + Vite, интерфейс оператора. |
| `apps/desktop` | `@gruber/desktop` | Electron shell: окно, splash, узкий preload-мост к нативным диалогам. |

В корне: `setup.mjs` (интерактивный мастер установки, ~2100 строк, со своим `setup.test.mjs`),
`launch.mjs` (запуск установленного приложения), `docs/`, `deploy/systemd/`,
`scripts/` (проверка репозитория и офлайн-комплект, тесты — `scripts/bundle.test.mjs`).

`FluxIO.fig` — 36 MB бинарный макет Figma в корне репозитория; к сборке отношения не имеет.

## Команды

```bash
npm run setup            # интерактивный мастер: зависимости, .env, PostgreSQL, сборка, запуск
npm run dev:server       # media-service в watch-режиме (tsx)
npm run dev:web          # Vite на 127.0.0.1:5173
npm run dev:desktop      # Electron поверх dev-сервера
npm run typecheck        # contracts + все workspaces
npm test                 # тесты всех workspaces + setup.test.mjs и launch.test.mjs
npm run db:migrate:dev   # новая миграция Prisma в разработке
npm run package:desktop  # installer под текущую ОС
```

Почти каждый скрипт начинается с `build:contracts` — это не украшение. `@gruber/contracts`
потребляется как скомпилированный `dist`, поэтому после правки схем **сначала** пересобери
contracts, иначе typecheck и dev-сервер увидят старые типы.

## Поток данных

```
Electron main (нативные диалоги) ──preload IPC──> React UI
                                                    │ HTTP + polling
                                                    ▼
                       Fastify media-service (apps/media-server/src/app.ts)
                          ├─ Zod-валидация запроса схемами из @gruber/contracts
                          ├─ DatabaseService (Prisma → PostgreSQL)
                          └─ PlayoutSupervisor
                               ├─ clip renderers (текущий + предзагруженный следующий)
                               ├─ scene producers (Skia → сырые RGBA в pipe:3, pipe:4…)
                               ├─ постоянный program encoder
                               ├─ GStreamer dvbsubenc (отдельный subtitle PID)
                               └─ TSDuck transport (PCR, CBR, SCTE-35, merge, зеркало для preview)
```

Rolling playout — самое важное для понимания: недельный плейлист **не** отдаётся FFmpeg целиком.
Один долгоживущий encoder, отдельный renderer на текущий ролик, следующий renderer уже запущен и
блокируется на pipe. Переход между роликами не сбрасывает PID, mux clock и TSDuck output.

Опрос из UI: health каждые 2 с, playout status ~каждые 750 мс (`apps/web/src/App.tsx`).

## Куда вносить изменение

**Новая настройка кодирования / выходного протокола** (сквозной путь, порядок важен):

1. `packages/contracts/src/index.ts` — поле в соответствующую Zod-схему (`videoEncodingSchema`,
   `audioEncodingSchema`, `mpegTsOutputSettingsSchema`, `udpEndpointSchema`, …).
2. `npm run build:contracts`.
3. `apps/web/src/types.ts` (`BroadcastSettings`) + `apps/web/src/default-broadcast-settings.ts`
   (значение по умолчанию).
4. `apps/web/src/screens/BroadcastSettingsScreen.tsx` — контрол.
5. `apps/web/src/App.tsx` → `buildStartRequest()` — перенос значения из UI-состояния в запрос
   (там же живут `normalize*` хелперы для приведения строк UI к литеральным типам контракта).
6. `apps/media-server/src/ffmpeg/command-builder.ts` или `src/tsduck/command-builder.ts` —
   собственно аргумент процесса.
7. Тест в `apps/media-server/src/app.test.ts`.
8. Если настройка сохраняется в профиль `.json` — `apps/web/src/encoding-settings-profile.ts`
   и `encodingSettingsFileSchema` в contracts.

**Новый HTTP-эндпоинт**: схема запроса/ответа в contracts → маршрут в подходящем модуле
`apps/media-server/src/router/v1/*Route.ts` → функция-обёртка в `apps/web/src/media-api.ts`
(весь клиентский HTTP идёт только через неё). Всё, что маршруту нужно от сервера, приходит одним
`RouteContext` из `src/router/context.ts`; там же общие ответы `badRequest` / `notFound` /
`databaseUnavailable`. Новый модуль маршрутов регистрируется в `registerRoutes()` в `app.ts`.
Для маршрутов, принимающих плейлист или расписание целиком, нужен
`{ bodyLimit: largePlaylistBodyLimitBytes }` — недельное расписание не влезает в дефолтный лимит
Fastify. Промах выглядит не как 413: служба перестаёт читать тело на ~750 КБ, и браузер, ещё
досылающий его, получает оборванное соединение — «Failed to fetch». Так `/api/schedule/serialize`
ронял и «Сохранить .txt», и автосохранение в FluxIO Sessions.

**Новый эфирный эффект второго уровня**: графика делится на уровни — 1 (логотип, возраст) и
2 (параметрические эфирные эффекты). Оформление эффекта отдельным элементом списка не является:
`decoration` в определении говорит, чем эффект оформлен — **сценой**, которую он рисует сам, или
готовым alpha-медиа (`effectDecoration` в `broadcast-effects.ts`; у `fileOnlyEffectKinds` —
Animation in/out и Stinger — выбора нет, только файл). Эффект уровня 2 не рисуется напрямую: он
*разрешается* в FX-слои, показы сцен и звуковые вставки, поэтому supervisor и TSDuck про уровни
не знают. Правь по цепочке: настройки в `broadcastEffectSettingsSchema` (contracts) → чистый
планировщик в `apps/web/src/broadcast-effects.ts` (+ тест) → панель в
`apps/web/src/screens/BroadcastEffectInspector.tsx`. Держись разделения «план — применение»:
`planBroadcastEffect` чистый. Инструкция оператора — `docs/graphics-and-titles.md`,
архитектурная карта потока — `docs/architecture.md`.

**Список эффектов только фильтруется, но никогда не сортируется.** Порядок задал оператор, и он же
определяет порядок наложения слоёв: `createBroadcastEffect` дописывает эффект в конец библиотеки,
`applyBroadcastPlan` — слои в конец `asset.effects`.

**Ролик без файла в эфир не уходит, но эфир из-за него не встаёт.** `playableClips` в
`apps/web/src/clip-duration.ts` (+ тест) снимает такие строки с запроса — и на старте, и на
горячей замене, потому что через `buildPlayoutItems` идут оба пути. Отдать их FFmpeg значит
уронить линию на первом же кадре; отказать в старте — оставить канал без эфира из-за одного
пропавшего файла. Оператор подставляет файл кнопкой **Link file** под живым эфиром, и ролик
возвращается ближайшей горячей заменой сам. Отметка старта и подъём по чекпоинту тоже идут
мимо нечитаемых: `firstPlayableFrom` берёт следующий читаемый, а не отказывается стартовать.

**Ролик без файла остаётся в расписании, но эфирного времени не занимает.** Строку собирал
оператор, и выбросить её значит соврать о времени выхода всего, что стоит ниже; держать за
ней минуты, которых в эфире не будет, — соврать так же, только в другую сторону. Поэтому
`airDurationSeconds` отдаёт для `status: "error"` ноль (одна функция на список, сводку дня,
догон по часам и общий хронометраж), строка красится красным той же силы, что зелёная у
идущего ролика, и получает кнопку **Link file** — она меняет файл, сохраняя опознаватель
строки со всей её обвязкой: титрами, AGE, логотипом, метками SCTE-35 и отметкой старта.

**Постановка ролика в расписание всегда создаёт новую строку.** Слияние по пути годится
медиатеке — там второй экземпляр файла не нужен, — но не расписанию: отбивки, заставки и
реклама идут в неделе десятками повторов, и `mergeAssets` их молча съедал (оператор жал
«добавить» и не видел ничего нового). Опознаватель строки поэтому не хеш пути, а
`newScheduleRowId` — иначе повторы склеились бы вместе со своими титрами, метками и
выделением. Место постановки задаёт `insertBeforeId`: `null` — в конец, иначе перед
указанной строкой; сброс файла на строку разрезает расписание по её середине.

**Разрезанный ролик — это части-строки и пометки между ними.** Кнопка «ножницы» в панели
плейлиста режет строку на отрезки одного файла: у части своя точка входа (`trimInSeconds`) и
длина (`declaredDurationSeconds`), поэтому эфир, отметка старта, горячая замена и SCTE-35 идут
с ней как с обычным роликом — `buildPlayoutItems` отдаёт выход как вход плюс длину. Между
частями встаёт строка `rowKind: "comment"` («Рекламный блок»): без файла и без хронометража,
`playableClips` в эфир её не пускает. Логика — чистый `apps/web/src/clip-split.ts` (+ тест),
окно — `components/ClipSplitDialog.tsx`. Три вещи, которые легко сломать:

- **Обвязка раздаётся частям по времени, а не копируется.** Метка SCTE-35 считается от файла и
  остаётся на месте; показ сцены, FX-слой и звуковая вставка уходят в ту часть, где начинаются,
  со сдвигом к её началу. Копия на каждую часть выпустила бы «Смотрите далее» в конце каждой
  части, а метка вне отрезка роняет старт («outside the active trim range»). Маркировка —
  исключение: возрастной знак показывают и после рекламы, поэтому его получает каждая часть.
- **Разрез обязан пережить `.txt`.** Часть пишется строкой `movie <вход> длительность путь`
  (синтаксис AirSheet), имя части — `insertName`, пометка — своей строкой `comment {…}` перед
  роликом `beforeItemIndex`. Без точки входа открытое заново расписание пустило бы вторую часть
  с начала фильма. Отдельной метки «это один фильм» файл не несёт: разрез узнаёт по стыку
  `splitGroupsFromSchedule`.
- **В медиатеку часть попадает целым файлом.** Импорт кладёт в `assets` строку без
  `trimInSeconds` и `splitGroupId`: медиатека сливает строки по пути, и следующая постановка
  оттуда встала бы с середины фильма.

**Отмена расписания слушает сами списки, а не каждую правку.** Правки приходят из десятка
мест — перестановка, удаление, AGE, логотип, эффекты, импорт, — и заводить историю в каждом
значило бы забыть её в одиннадцатом. История в `App.tsx` сравнивает ссылки на `playlist` и
`futurePlaylist`: любое изменение — шаг. Восстановление сессии шагом не считается
(`applyingHistory`), иначе первое же «Отменить» возвращало бы пустое расписание, которое
было до загрузки снимка.

**Эффект назначается на ролик только со вкладки Effects.** В строке плейлиста стоит **полка
титров** — она показывает, что на ролике уже лежит, и ничего не добавляет. Выпадающий список
«FX» оттуда убран: с v8 библиотека содержит только эффекты второго уровня, а они сами решают,
куда и когда лечь, — список был пуст и всегда заблокирован. Полка обязана читаться на
прокрутке: пустая — пунктиром, занятая — сплошной рамкой со счётчиком, и то же самое значком
у свёрнутой строки. Ради этого её и делали: инженер ведёт эфир, листая расписание, а не
открывая каждый ролик.

**Оформление рисует сцена, а не внешний формат.** С v8.0.0 Lottie/After Effects из проекта убраны
полностью: шаблон — это дерево узлов (`sceneTemplateSchema` в `packages/contracts/src/scene.ts`),
а рисует его **одна общая функция** `drawScene` из `packages/scene-renderer`. Её вызывают из двух
мест — редактор в браузере и графический процесс в эфире. **Второй реализации отрисовки быть не
должно**: как только она появится, предпросмотр разойдётся с выходом, а текст сможет появиться
раньше своей плашки — ровно та ошибка, из-за которой формат и сменили.

Три вещи в этой связке легко сломать:

- **Время берётся из номера кадра, а не из системных часов.** Рендерер следующего ролика
  запускается заранее и по часам нарисовал бы будущее — тот же капкан, что у экранных часов.
- **Область считается после промера текста.** Привязанная плашка растёт по строке
  (`sceneFitToTextSchema`), поэтому `measureSceneText` идёт **до** `sceneRegion`: область,
  посчитанная без промера, срезает длинную надпись по краю.
- **Рисуется только область, а не кадр целиком.** Полный кадр 2160 RGBA — это 829 МБ/с, и в
  реальное время он не укладывается: измерено в Ф0, извлечение пикселей и запись в трубу
  дороже самой отрисовки. `sceneShowRegion` берёт объединение по всему показу — `overlay`
  получает одно фиксированное смещение на весь показ, и менять его покадрово нельзя.

Координаты — доли кадра; `x` и `width` считаются от ширины, а **`y`, `height`, кегль, радиус и
размытие — всегда от высоты**, иначе раскладка едет между 4:3 и 16:9. Раскладок четыре
(`sd-4x3`, `sd-16x9`, `hd`, `uhd`), частота рисования у чересстрочных режимов — **в полях**
(50i рисует 50 раз в секунду).

**Надпись, вписанная в рамку, уменьшает кегль, а не ширину.** Значение поля приходит извне —
из файла задания, из выгрузки `.json`, — и длину его никто не выбирает: в одну плашку приезжают
и «Иван», и «Александр Константинопольский». Галочка «Вписывать в рамку» (`textStyle.autoFit`)
считает масштаб одной функцией `textAutoFit` на промер и на отрисовку — разойдись они, плашка
села бы по одной ширине, а буквы вышли другой. Рамкой служит **базовое** значение ширины узла:
анимированное дёргало бы кегль вместе с раскрытием плашки. Ниже `autoFitMinScale` не сжимаем —
строка, ужатая в десять раз, читается не лучше срезанной, — а упёршуюся в минимум режет сама
рамка. Сжимать по горизонтали нельзя: буквы поедут, и видно это только в эфире.

**Режиссёр показа — `in / hold / out`.** Оператор задаёт только момент и длительность; удержание
растягивается, а вход и выход сохраняют свою длину. Если длительности не хватает на обе половины,
`sceneTiming` сжимает **обе** — оборвать выход на середине хуже, чем проиграть быстрее.

**Новый тип узла сцены или новое свойство**: схема в `packages/contracts/src/scene.ts` →
`npm run build:contracts` → чистые функции раскладки и времени в `scene-timing.ts` (+ тест) →
отрисовка в `packages/scene-renderer/src/draw.ts` (+ тест на `RecordingSurface`) → инспектор
редактора. Растеризатору в эфире правка не нужна: `apps/media-server/src/scene/surface.ts`
только создаёт полотно, регистрирует шрифты и отдаёт пиксели. **Если пришлось потрогать
`surface.ts` ради нового свойства — почти наверняка логика попала не в тот слой.**

Новый узел обязан честно отвечать на два вопроса: сколько места он занимает (`resolveNodeBox`,
иначе он не попадёт в область и будет срезан) и что делает вне окна показа. Тест на
`RecordingSurface` пишется без запуска процессов — она записывает вызовы отрисовки, а не
сравнивает картинки.

**Правка редактора титров**: чистая логика — `apps/web/src/scene-edit.ts` (+ тест), интерфейс —
`apps/web/src/screens/TitleEditorScreen.tsx` и `apps/web/src/title-editor/*`. Редактор — накладка
поверх приложения, а не вкладка: открывается из эффекта со сценой и возвращает в него.

Три вещи, на которых он ломается тише всего:

- **Перетаскивание считается от снимка узла на момент захвата.** Это единственный способ,
  переживший проверку. Запись готовой координаты в базовое значение уводит анимированный узел мимо
  места, куда его положили: холст рисует значение *с ключей*. Разница от прежнего шага складывается
  сама с собой — узел улетает из кадра тем дальше, чем дольше его тащат. Разница от прежнего
  **применённого** шага теряется, когда React сводит несколько событий мыши в одну отрисовку:
  экран правит шаблон из своего замыкания, и движения затирают друг друга. Поэтому холст держит
  `origin` — узел на момент нажатия, — считает всё от него и отдаёт **готовый узел**.
- **Узел для перетаскивания берётся в момент захвата, а не из выделения.** Выделение обновляется
  следующей отрисовкой, и при быстром «нажал и потащил» первые движения ушли бы прежнему узлу.
- **Зона захвата мышью считается тем же промером текста, что и рисунок.** Без промера привязанная
  плашка ловится не там, где нарисована: снаружи это выглядит как «элемент не там, где виден».
- **Перенос точки привязки не двигает узел.** Дизайнер выбирает точку отсчёта, а не элемент:
  `setNodeAnchor` правит положение ровно настолько, чтобы картинка не изменилась, и правит **всю
  дорожку**, иначе анимация отрывается от узла.
- **Порог прилипания задан в пикселях экрана**, а не в долях кадра: доля в полпроцента на мелком
  предпросмотре меньше пикселя, и прилипание перестаёт работать там, где оно нужнее всего.
- **Кривая ускорения принадлежит ключу, к которому идёт**, а не от которого. Так же устроен график
  скорости в After Effects. По X ручки зажаты в 0..1: кривая, у которой время идёт назад, даёт у
  одного момента два значения. По Y предела нет — отскок за диапазон это законный приём.
  Решение уравнения по X идёт Ньютоном с подстраховкой делением пополам: на плоских участках
  производная уходит в ноль и Ньютон расходится.
- **Таймлиния показывает все слои, но раскрывает только анимированные свойства.** Понять, где
  вообще что-то происходит, иначе нечем, а полный список из одиннадцати дорожек на каждый слой
  невозможно читать. Свёрнутый слой отдаёт сводную полосу с положением ключей.
- **Группа-контейнер берёт размер от ребёнка, а не от кадра.** `setGroupContainer` ставит
  `fitToNodeId` (обычно подложка) и включает `clipsChildren`: без собственных границ у контейнера
  нечего прятать, и раскрытие резало бы содержимое по краю кадра. Одно раскрытие группы прячет
  весь текст разом — вместо ключа на каждый слой.
- **Разнос появления текста — доля, а не секунды.** Длительность входа задаёт режиссёр, и волна
  обязана укладываться в неё при любой длине строки. Готовые наборы — `textAnimatorPresets`
  в `scene-edit.ts`, разбор строки и сдвиг частей — `textUnits` / `splitUnits` в `scene-timing.ts`.
- **Узел внутри группы сдвинут вправо на всю строку**, и группа сворачивается. Сдвиг одного имени
  читался как случайный отступ, а не как вложенность; сдвиг есть и в списке слоёв, и на таймлинии —
  две колонки об одном и том же читаются как одна, только пока вложенность в них выглядит одинаково.
- **Точка среза маски едет за привязкой.** Раскрытие обязано выезжать оттуда же, откуда считается
  сам узел. Проверять, «не увели ли срез вручную», нельзя: у шаблонов прежних версий срез стоит по
  старому умолчанию, и такая проверка молча не срабатывала бы ровно там, где перенос привязки и
  нужен. Увести срез отдельно можно — сеткой 3×3, уже после переноса привязки.
- **У группы привязка переносится без поправки.** У обычного узла `x` и `y` — положение, и поправка
  оставляет картинку на месте. У группы это **сдвиг**, который складывается с детьми, а собственная
  коробка берётся от узла-подложки: та же поправка утаскивает всё содержимое на ширину плашки.
- **Текст правится двойным щелчком прямо в кадре.** У статичного узла правка идёт в сам текст, у
  привязанного к полю — в образец поля: править надо то, что рисуется, иначе правка не видна. Часы,
  отсчёт и бегущую строку так не правят — у них своё содержимое, и поле ввода поверх них обещало бы
  правку, которой не будет.
- **Превью эффекта одно, и сцену в нём рисует `drawScene`.** Двух превью не бывает: у сцены и
  макета положения разная правда о кадре, и оператор верил бы тому, что увидел первым. Макет
  (`BroadcastEffectPreview`) остаётся только там, где оформление задано файлом и рисовать нечего.
  Длительность показа берётся `sceneShowDurationSeconds` — одним помощником на редактор,
  предпросмотр и эфир: разойдись они, вход и выход шли бы не там, где выйдут в кадр.
- **Редактор открывает сохранённую сцену эффекта, а не чистый холст.** Собранная однажды плашка
  уходит в эфир, и если «Править в редакторе титров» каждый раз начинает заново, править её
  больше нечем. Черновик (`sceneDrafts`) отвечает ровно за одно — незакрытая правка переживает
  «Закрыть», — живёт только до перезапуска и на «Сохранить» стирается: источник правды с этого
  момента `broadcast.scene` самого эффекта, и он же переживает сессию. Чистым холстом редактор
  открывается только у заводского оформления, с которым эффект создан (`editableSceneTemplate`
  в `default-scenes.ts`); его опознаватель собран из переведённого названия, поэтому заводскими
  считаются оба языка.
- **Имя эффекта правит оператор** — полем в шапке инспектора и двойным щелчком в списке.
  «Динамическая плашка (2)» не говорит, что это за титр, а в списке из двух десятков различать их
  больше нечем. Поле неуправляемое (правка на каждое нажатие клавиши перерисовывала бы всё дерево),
  поэтому оно пересоздаётся по ключу с именем — иначе переименование из списка не доходит до шапки.
- **Точки градиента заданы долями коробки узла, а не кадра.** Градиент принадлежит узлу и обязан
  ехать вместе с ним при смене раскладки. У радиального центр берётся из первой точки, радиус —
  расстоянием до второй: одна пара точек на оба вида, чтобы переключение не сбрасывало настройку.
  Точки перехода отдаются канве **по возрастанию доли** — она их не сортирует, и точка, поставленная
  раньше своей очереди, у части реализаций просто теряется.
- **Значения титра — по полям сцены, а не по двум зашитым ключам.** Пара «строка плюс подпись»
  перестала описывать титр, как только плашку стало можно собрать самому: ключи объявляет сцена,
  их может быть сколько угодно. Значения оператора лежат в `settings.dynamicTitle.fieldValues`;
  сессии до v8.0.2 читаются через `text` / `captionText` — пустой `default` погасил бы титр,
  который уже выходит в эфир.
- **«Смотрите далее» кладёт название в то поле сцены, которое выбрал оператор.** Ключи объявляет
  сцена, инспектор показывает их списком, а пишет значение `nextProgramSceneFields`. Раньше пара
  `title` / `subtitle` была зашита в планировщик, и выбор в «Поле названия» ни на что не влиял:
  плашка со своим ключом молча выходила в эфир с образцом вместо названия. Ключ, которого в сцене
  нет, — это умолчание (`next_title`, с ним эффект и создаётся), а не выбор оператора: такое
  значение уходит в общепринятые `title` / `subtitle`, иначе плашки, уже идущие в эфир, разом
  остались бы без текста.
- **Часы и отсчёт привязываются так же — полем, но эффект меняет источник узла, а не текст.**
  Готовое значение подставить нельзя: время считает рендерер по номеру кадра, а посчитанная на
  планировании цифра ушла бы в эфир замороженной. Поэтому `withClockMode` ставит выбранному узлу
  источник `clock` / `countdown` с режимом и форматом эффекта. Ключ, не объявленный сценой, снова
  значит «не выбирали»: тогда часами становится каждый узел, у которого источник уже такой, — на
  этом держится заводская сцена. И отдельно: поля сцены, которым эффект ничего не даёт, уходят в
  эфир **своим образцом** (`clockSceneFields`) — рендерер отдаёт для необъявленного ключа пустую
  строку, и подпись, объявленная полем, молча пропадала бы из кадра.
- **Файл задания связывается совпадением имён, а не маппингом.** Запись находит свой ролик по
  ключу `dataMapping.matchSourceKey`, а значения берутся по **тем же** именам, что у полей сцены.
  Ролик, которому записи не нашлось, титра не получает: поставить его с резервным текстом значит
  выпустить в эфир чужие данные.
- **Ключ сопоставления выбирается по значениям, а не по имени ключа.** В реальной выгрузке `name` —
  это имя гостя, а имя ролика лежит в `title`; выбор по знакомому слову молча давал ноль
  совпадений. `preferredMatchKey` проверяет каждый ключ расписанием и берёт тот, чьи значения
  совпали с наибольшим числом роликов.
- **Обёртка файла задания снимается по форме, а не по имени.** Выгрузки приходят обёрнутыми именем
  блока (`{"lower": [...]}`), и у каждой системы оно своё. `unwrapTaskDocument` снимает **ровно
  один** непустой массив объектов — метаинформация рядом не мешает, два списка сразу это уже
  догадка, а угаданное неверно тихо подменило бы данные эфира.
- **Способов применения три, и они в одном месте — в конце.** На ролик, на весь проект и по файлу
  задания. Откуда брать значения, решает нажатая кнопка, а не отдельный селектор «источник текста»:
  лишний переключатель оператор забывает переставить, и титр выходит с резервным значением вместо
  данных задания. Файл выбирается там же, где по нему раскладывают.
- **Ключей в удержании не бывает.** Оно растягивается под длительность показа, и ключ в нём заставил
  бы картинку зависеть от неё. Кнопка в удержании заблокирована, время ключа отсчитывается от начала
  своего отрезка.
- **Раскрытие — обрезка, а не изменение размера.** Анимировать ширину у текста нельзя: буквы
  поедут и сожмутся вместе с ней. Маска (`reveal` в `sceneTransformSchema`, `revealClip` в
  `scene-timing.ts`) открывает уже готовую картинку узла, не трогая её. Точка среза задаёт, откуда
  маска растёт, — она же в инспекторе сеткой 3×3, как точка привязки.
- **Раскрытий два, и путать их нельзя.** `revealMode: "slide"` (умолчание) — выезд: рамка стоит,
  картинка выползает из-за её края со стороны точки среза (`revealShift`). `"wipe"` — шторка:
  окно растёт от точки среза, картинка неподвижна. «Раскрытие» на слух и на глаз — это выезд, и
  шторка под этим словом оператора обманывала; шторка осталась готовым входом «Развёртка» и
  переключателем в инспекторе. Выезд группы везёт и содержимое (`ancestorRevealShift`), а узел,
  уехавший за маску целиком, не рисуется вовсе — считать невидимое в реальном времени нечем.
- **Коробка группы — габариты её содержимого, а не собственный прямоугольник.** Своя ширина у
  группы жила отдельной жизнью: рамка стояла там, где её однажды растянули, а картинка ехала
  сама по себе — обрезка резала по пустому месту, маска выезжала из-за края кадра, поворот шёл
  вокруг точки вне содержимого. Считает габариты `groupContentBox` в `scene-timing.ts`; пустая
  группа остаётся при своих дорожках, чтобы рамка не схлопнулась в точку. Явную рамку по-прежнему
  задаёт `fitToNodeId` (`setGroupContainer`). Отсюда же следствия: сборка в группу **не трогает
  детей** (`x`/`y` группы — нули до первого перетаскивания), а ручки размера пишут в масштаб
  (`scaleGroupBox` в `scene-edit.ts`), потому что менять у группы нечего, кроме содержимого.
- **Рамка выделения на холсте рисуется по нарисованному, а не по раскладке.** Масштаб и поворот
  живут преобразованиями холста и в `resolveNodeBox` не попадают, поэтому `SceneCanvas` доводит
  коробку через `ancestorTransforms` + `transformedBounds`. Тем же прямоугольником ловится мышь:
  посчитай их по-разному — и «элемент не там, где виден» вернётся с другой стороны.
- **У группы точка привязки не двигает её коробку.** `x` и `y` группы — сдвиг содержимого, а
  коробка служит рамкой обрезки и точкой отсчёта поворота. Вычесть из неё привязку значит увести
  рамку от детей: они считают место от того же `x` и остаются, а рамка уезжает — и с включённой
  обрезкой режет по пустому месту. У примыкающего (`fitToText.anchor: "follow"`) узла то же
  правило с другой стороны: его место задаёт правый край источника, поэтому привязка
  прибавляется обратно в `followOffset`, а `setNodeAnchor` в такой узел поправку не пишет.
- **Группа ловит мышь всей коробкой, и порядок зон захвата задан явно.** Собранную плашку
  тащат по кадру целиком — ради этого группа и нужна, — поэтому у группы есть своя зона
  захвата. Полагаться на порядок в разметке нельзя: группа стоит в списке **выше** своих
  детей и накрывала бы их всегда. Невыбранная группа лежит под содержимым (`zIndex` 0 против
  1 у узлов) — щелчок по узлу берёт узел; у выбранной зона поверх (`zIndex` 3), иначе
  «взялся за группу» означало бы «потащил один узел». Рамка выделения и ручки при этом
  обязаны быть ещё выше (`.scene-frame`, `zIndex` 4), а `Alt` проваливается сквозь группу
  к узлу под курсором — иначе к содержимому выбранной группы не добраться мышью вовсе.
- **Прокрутка дорожек времени живёт в списке слоёв, а не в панели.** `overflow-y: auto` при
  `overflow-x: visible` CSS сам доводит до `auto` по обеим осям — и ключ на конце показа,
  выходящий за свою дорожку на половину значка, заводил боковую полосу на всю панель.
  Поэтому у списка слоёв `overflow-x: hidden` плюс правый отступ под этот выступ, а высоту
  ему отдаёт сетка панели: потолок в `vh` рядом с высотой от разделителя давал вторую
  прокрутку поверх первой.
- **Захват указателя на перемотке обязан отпускаться.** Незакрытый `setPointerCapture` оставляет
  головку времени ходить за мышью после того, как кнопку отпустили: снаружи это выглядит как
  «ползунок прилип». Отпускаем и на `pointerup`, и на `pointercancel`, и на `lostpointercapture`.

Выделение в редакторе держится **одним** состоянием (активный узел плюс остальные). Двумя
состояниями это уже ломалось: при Ctrl-щелчке второй вызов читал прежний активный узел из
устаревшего замыкания, и набор не набирался.

Группа — это узел-родитель: её сдвиг и прозрачность складываются с детьми в `resolveNodeBox`.
Ради этого она и нужна — чтобы плашка с текстом ехала как одно целое, а не тремя одинаковыми
наборами ключей, которые рано или поздно разъедутся. Группа встаёт **на место самого верхнего**
из выбранных: порядок в списке это порядок наложения, и всплытие наверх переставило бы слои.

Дорожки времени **не прячутся** без выбранного слоя — только приглушаются. Исчезающая полоса внизу
дезориентирует: экран прыгает, и оператор перестаёт понимать, где вообще живёт анимация.

Предупреждения о безопасной зоне выдаются **только для текста**: плашка и полоса бегущей строки
уходят за край намеренно, и предупреждение на каждую — шум, который приучает не читать список.

**Аппаратное кодирование** живёт в `apps/media-server/src/ffmpeg/hardware-encoder.ts` —
чистые функции, потому что ускорителя на машине разработчика может не быть, и проверять выбор
надо тестом. Три правила, каждое из которых стоило бы эфира:

- **Подмены на программный кодировщик не бывает.** Оператор выбрал ускоритель потому, что
  программный не тянет профиль; тихий откат вылез бы в эфире пропущенными кадрами. Недоступный
  ускоритель — отказ preflight с именем кодировщика.
- **Чересстрочность умеют не все.** Отдать прогрессив вместо 50i — не «чуть хуже», а
  несовпадение с профилем: головная станция ждёт поля. Ловится
  `hardwareSupportsInterlace` до старта.
- **Предпросмотр всегда программный.** Ускоритель у машины один, и предпросмотр, взяв его,
  отбирал бы ресурс у эфира. `buildFfmpegCompositePreviewCommand` передаёт `softwareEncoder`
  явно.

У ускорителей свои пресеты и своё управление скоростью: параметры x264 они не понимают.
VAAPI вдобавок кодирует в памяти ускорителя, поэтому ему дописывается ступень
`format=nv12,hwupload` — **в тот же граф**: второй `-filter_complex` FFmpeg молча заменяет первый.

**Медиа в сцене не рисует растеризатор.** Видео с альфой и `.png`-последовательность
разрешаются в обычный FX-слой (`pushSceneMedia` в `broadcast-effects.ts`) и попадают в кадр
через FFmpeg — тем же путём, каким уже идут стингер и Animation in/out. Декодировать видео
покадрово в том же однопоточном процессе, что считает титр, значит не успеть к кадру.
Длина показа подгоняется под источник: титр короче подложки обрывал бы её на середине.

**Файл титра `.fto`** — «FluxIO Title Object», JSON с меткой формата
(`titleFileSchema` в contracts). Своё расширение взято намеренно: с `.json` титр
не отличить от файла задания или профиля настроек, и оператор узнавал бы об
ошибке уже при разборе. Метка и версия обязательны — чужой или будущий файл
обязан отклоняться внятно, а не разбираться наполовину.

Каталог титров — папка `FluxIO Titles` на рабочем столе, её создаёт `setup.mjs`
и кладёт туда **базовый набор** из `assets/titles/*.fto`. Уже лежащий файл не
перезаписывается: оператор мог поправить шаблон под свой канал, и обновление
стёрло бы правку молча.

Сам набор описан кодом — `packages/contracts/src/title-presets.ts`, — а
поставляется файлами: в папке он лежит рядом с тем, что оператор соберёт сам, и
ничем от него не отличается. Файлы пересобираются из кода:

```bash
node --input-type=module -e "import { builtInTitlePresetFiles } from './packages/contracts/dist/index.js'; import { writeFile } from 'node:fs/promises'; for (const { fileName, file } of builtInTitlePresetFiles('8.0.0')) await writeFile('assets/titles/' + fileName, JSON.stringify(file, null, 2) + '\n');"
```

Набор проверяется тестом, а не на глаз: уникальность id узлов, объявленность
полей с образцами, целость привязок, отсутствие колец в цепочке привязок,
попадание в зону надписей и совпадение конца входа с началом выхода. Первый же
из этих тестов поймал метку «В эфире», уехавшую за правый край.

**Привязка `fitToText` умеет две вещи.** `grow` — узел стоит на месте и растёт
по тексту: так ведёт себя подложка. `follow` — узел сохраняет ширину и
**примыкает** к правому краю источника: так держится хвост плашки, и источником
здесь может быть любой узел, в том числе сама подложка. Без `follow` хвост
отрывается от подложки, как только заголовок оказывается длиннее образца, —
и заметно это только на реальном тексте.
**Загруженный шаблон получает новые опознаватели узлов** (`adoptTitleTemplate`):
два узла с одним id — это потерянная привязка плашки к тексту, и заметно это
только в эфире.

**Проект хранит пути, а не файлы**, и это верно не только для FX-слоёв: у
эффекта второго уровня свои файлы — оформление Animation in/out, файл перехода,
подложки узлов сцены. Их проверяет `effectLibraryPaths` /
`collectMissingEffectFiles`, и пропажа показывается окном сразу после
восстановления сессии, а не отказом на Start.

**Расписание `.txt` несёт эфирные эффекты.** Определение пишется **один раз**
заголовком файла (`defineBroadcastEffect`), ролики ссылаются на него
опознавателем (`insertBroadcastEffect`): один титр на двухстах роликах иначе
означал бы двести копий сцены в одном файле. Определение и значения полей едут
в base64 — расписание разбирается построчно по фигурным скобкам, а в JSON сцены
их полно. Показ без определения — отказ разбора, а не тихий пропуск: молча
пропущенный титр снаружи выглядит как «не вышел в эфир».

**Расписание объявляет пути, и панель ресурсов заполняется ими при импорте.** Логотип, картинки
маркировки, файлы перевода и субтитров лежат в файле абсолютными путями, а панель после импорта
оставалась пустой: оператор видел «Not selected» там, где расписание всё принесло само, и шёл
выбирать папки заново, не зная, что подхватилось. `librariesFromSchedule`
(`apps/web/src/schedule-libraries.ts`, + тест) выводит папку из самих путей и **на диск за этим
не ходит**: чужое расписание почти всегда приносит пути с другой машины, и сканирование молча
отдало бы пустой список вместо записанного в файле — что из этого существует, показывает
проверка графики следом. Папка считается по большинству вхождений: у одного ролика логотип
бывает свой, и папка от первого попавшегося пути увела бы не туда.

**Картинка маркировки едет в расписании рядом с текстом** — `insertAgeTitle {16+} duration {10}
path {…}`. По одному «16+» папку AGE на другой машине не найти, и маркировка уходила бы в эфир
нарисованной шрифтом (а для этого нужен FFmpeg с libfreetype). Поле необязательное: у расписаний
прежних версий пути нет, и выдумывать его нельзя — подставленная наугад папка отправит оператора
искать картинки не там.

**Первый выбор папки субтитров включает их всем, кому нашёлся файл.** Оператор выбрал папку
именно затем, чтобы субтитры пошли в эфир; обходить сотню роликов ради галочки на каждом — работа,
которой он не просил. Дальше `reconcileSubtitleAssignments` трогает только уже включённые:
выключенный ролик выключили намеренно, и возвращать ему субтитры при каждой смене папки значит
спорить с оператором.

**Метка SCTE-35 едет в расписании строкой `insertCue`.** Врезку ставит оператор по хронометражу,
и хронометраж принадлежит строке, поэтому метка идёт вместе с графикой ролика — как `insertAgeTitle`
и `insertLogoTitle`. Пустая пара скобок в `duration {}` — это конец врезки, у которого длительности
нет. Опознаватель метки при разборе собирается заново: он живёт внутри сессии, а расписание
переносят между машинами.

**Расписание занимает окно целиком, а не сумму своих роликов.** Оно привязано ко времени суток,
поэтому `fitScheduleWindow` режет всё, что вылезло за 168 часов (доиграв, эфир уехал бы вперёд и
вёз бы сдвиг до конца недели), а недостачу добивает заставкой оператора — при пустом поле
цветными полосами. Заставка идёт `-stream_loop -1` и на всё оставшееся время: перезапуск процессов
раз в её длину головная станция видит как обрыв, а не как заставку. Переход Current → Future
повторяется бесконечно: окно наследуется целиком, а `updateNextPlaylist` разрешён и после
промоушена — иначе следующее расписание некуда было бы залить.

**Тип воспроизведения выбирает оператор, и живёт он в метаданных расписания.** У эфира две
разные жизни: список файлов, который пускают с любого места и крутят по кругу, и сетка, привязанная
к часам, где зритель ждёт передачу в своё время. `playbackMode` в `workspaceScheduleMetadataSchema`:
`free` — старт с любого ролика, по кругу; `planned` — оператор задаёт начало и конец, промежуток
между ними и есть время заполнения (`anchorDate` + `startTime`, `targetDurationSeconds`), старт с
любого ролика в любой момент до конца; `weekly` — то же окно ровно на неделю, но старт **только по
часам** (`playbackStart` поверх `scheduleCatchUpPoint`). После конца окна Start отказывает с
причиной, недельное — ещё и до начала недели. Форма в метаданных, а не в настройках станции: у Current и Future
она своя, и Future уходит в эфир со своей. Логика — `apps/web/src/playback-mode.ts` (+ тест), окно —
`components/PlaybackModeDialog.tsx`. Само оно открывается **один раз за запуск** — когда плейлист с
роликами впервые на экране (после Import или восстановления сессии), — а дальше тип меняют кнопкой
«Изменить тип эфира» в панели плейлиста рядом со стартом и строкой режима в окне расписания: окно
на каждом переходе мешало бы работать с уже выбранным типом. Три вещи, которые легко сломать:

- **Эфир кончается в конце окна, а не через «столько-то» от старта.** `withPlaybackMode`
  применяется к запросу последним, после среза с середины ролика, и ставит окно до конца от этой
  минуты — и у планируемого, и у недельного: опоздавший старт не имеет права увезти эфир за край,
  после которого идёт следующая программа.
- **Конец недели — то же время суток через семь дней** (`setDate(+7)`), а не старт плюс 168 часов:
  с переводом часов они расходятся на час. Поэтому потолок `scheduleDurationSeconds` не ровно неделя.
- **Не выбран — прежнее поведение.** Сессии до этой версии поля не несут, и навязать им недельный
  режим значило бы молча запереть старт с ролика. Выбранный тип сам решает повтор, поэтому кнопка
  «Повтор» в настройках при нём заперта и показывает его положение: две кнопки об одном и том же
  рано или поздно разойдутся.

**Автостарт после запуска** (`autoResumeOnLaunch`) поднимает эфир, если в чекпоинте
стоит `interrupted`. Перед подъёмом идёт видимый обратный отсчёт с отменой: машину
перезагружают и ради обслуживания, и уходящий сам в линию эфир обязан быть заметен до
того, как он уйдёт. В профиль кодирования эта настройка **не входит** — она станционная,
а не переносимая.

**Место подъёма считается по часам, а не по месту обрыва** (`scheduleCatchUpPoint` в
`apps/web/src/schedule-timeline.ts`, тест там же). Расписание привязано ко времени суток:
подъём с места обрыва после часового простоя сдвинул бы эфир на час и вёз бы этот сдвиг до
конца недели. Длительность строки берётся **та же**, что и у списка расписания, — разойдись
они, строка «в эфире с 12:40» показывала бы одно, а подъём начинался с другого. Чекпоинт
остаётся запасным путём: на плейлисте без расписания часам опереться не на что.

**Смещение старта живёт в самой отметке** (`scheduleStartMarker.offsetSeconds`), а не
отдельным состоянием: оператор выбирает точку эфира один раз — «с этой передачи, с 40-й
секунды», — и после перезапуска она обязана вернуться вместе с отметкой. Срез с середины
ролика собирает **один** помощник `offsetStartRequest` на все три пути (восстановление,
отметка, «взять в эфир»): разъехавшись, они дали бы графику, которая на одном из путей
выходит не там.

**Новая звуковая дорожка / язык**: сопоставление файлов `{язык} <имя ролика>` живёт в
`apps/media-server/src/audio/tracks.ts` (там же ffprobe длительности каждого найденного файла),
таблица языков → ISO 639-2 — в `audio/languages.ts`.
Языки переводов объявляются **заголовком расписания** (`defineAudioLanguage`) — так же, как
эфирные эффекты: файл открывают на другой машине и через неделю, а пересканировать папку
переводов при открытии нечем. У расписаний прежних версий заголовка нет, поэтому разбор
собирает языки из самих строк `insertAudioTrack`: молча пустой набор языков снаружи выглядит
как «переводы пропали». По той же причине папка переводов пересканируется при восстановлении
сессии — сохранённого списка языков мало, дорожки ролика это пути к файлам, и их надо снова
найти на диске.
Набор дорожек программы фиксируется на Start (PMT неизменна): его строит
`apps/web/src/audio-program.ts`, каждая дорожка получает свой PID подряд от `udpAudioPid`.
Ролик без перевода отдаёт тишину, PID из PMT не пропадает.

**Новая запись в журнал**: суточный журнал живёт в `apps/media-server/src/logging/`.
`daily-log.ts` — чистые функции (формат строки, имя файла, накопление статистики), `logger.ts` —
запись на диск. Разовое событие — `context.logger.log(level, category, message)`; всё, что
относится к работе эфира, набирается из снимков `PlayoutStatus` в `observeStatus` на опросе
`/api/playout/status`. **Не разбирай текст событий supervisor'а** — он меняется, поля контракта нет.
Журнал не имеет права уронить эфир: ошибки записи гасятся внутри `logger.ts`.

**Новая операция с БД**: отдельный файл в `apps/media-server/src/database/operations/`, функция
первым аргументом принимает `DatabaseContext` (Prisma-клиент + шифр секретов). Затем тонкий метод
делегата в классе `DatabaseService`, чтобы вызывающий код не менялся. Преобразования строк БД
живут в `database/mappers.ts`, работа с recovery checkpoint — в `database/checkpoint.ts`,
шифрование SRT/RTMP секретов — в `database/secrets.ts`.

**Изменение поведения эфира**: `apps/media-server/src/ffmpeg/playout-supervisor.ts`. Приватные
методы `#prepareLoopCommands`, `#transitionToFutureSchedule`, `#spawnTsdDuck`, `#spawnDvbSubtitles`
— основные точки. Чистые хелперы вынесены в конец файла как экспортируемые функции
(`alignHotChangePlaylist`, `measurePcmS16leDbfs`, `shouldTransitionToFutureSchedule`, …) именно
чтобы их можно было тестировать без запуска процессов — держись этого приёма для новой логики.

**Правка установки без интернета**: комплект собирает `scripts/build-offline-bundle.mjs` на
машине с интернетом, ставит его `setup.mjs --bundle` на машине без неё. Три модуля делят
работу: `bundle-manifest.mjs` — описание и контрольные суммы (общий для обеих сторон),
`bundle-runtime-closure.mjs` — какие `node_modules` едут, `bundle-migrations.mjs` — схема,
`bundle-install.mjs` — сторона целевой машины. Ни один из них не зависит от `@gruber/contracts`:
мастер работает **до** любой сборки и обязан подняться на голом Node.

Три вещи в этой связке легко сломать:

- **Комплект собирается на машине той же платформы и архитектуры.** Electron, `@napi-rs/canvas`
  и весь медиастек между платформами не переносятся, поэтому сборщик отказывается собирать
  чужую цель. Прочее платформо-независимо: Prisma 7 работает через WASM-компилятор запросов,
  движка-бинаря в рантайме нет.
- **В `node_modules` едет замыкание, а не всё дерево.** TypeScript, Vite, electron-builder и
  Prisma CLI нужны только сборщику. Необязательные зависимости берутся, только если они есть на
  диске: у нативных пакетов там перечислены все платформы сразу.
- **Приложение macOS копируется со ссылками, а не по содержимому.** У `.app` фреймворки собраны
  символическими ссылками (`Versions/Current` → `Versions/A`), и копирование с `dereference`
  превращает 319 МБ в 851 МБ полных копий. Поэтому `cp` идёт с `verbatimSymlinks`, а отпечаток
  описывает ссылку её целью: подменённая ссылка — это подменённый фреймворк.
- **Обновление переносит компоненты, а не перезаписывает установку.** Новый комплект
  распаковывается рядом, `--update=<каталог>` переносит только изменившиеся компоненты и
  передаёт работу мастеру установленного каталога (`projectRoot` считается от расположения
  файла, поэтому дальше должен работать именно тот мастер). `data/` компонентом не является и
  не трогается вовсе, а `app/.env` лежит **внутри** заменяемого компонента — его уносят и
  возвращают руками, иначе обновление стоило бы оператору всей настройки станции.
- **Единый файл — это заголовок `sh` и приклеенный архив.** Заголовок отсчитывает свои строки
  (`tail -n +N`), поэтому номер строки подставляется **после** его сборки и плейсхолдер обязан
  жить на одной строке: иначе подстановка сдвинет счёт, и распаковка начнётся с середины архива.
  Архив пакует системный `tar` — он есть на всех трёх платформах и сохраняет бит выполнения, без
  которого медиастек в комплекте бесполезен.
- **У API нет аутентификации, и это решение, а не упущение.** FluxIO ставится на выделенную
  эфирную машину, которой управляет один человек и которая не смотрит в интернет; доступ
  ограничивается сетью, а не приложением. Серверный профиль лишь открывает порт и раздаёт
  интерфейс из Fastify (`GRUBER_WEB_DIR`) — маршруты эфира при этом доступны всем, кто дотянулся
  до порта. Появится задача разделять операторов — это будет новая возможность, а не починка.
- **Кластер PostgreSQL из комплекта разворачивается в каталоге установки** (`bundle-postgres.mjs`),
  и трогать уже стоящий на машине сервер он не имеет права. Здесь три ловушки, каждую видно
  только на живой машине: путь к Unix-сокету ограничен ядром (~103 байта), и глубокий каталог
  установки не даёт postmaster стартовать вовсе — сокет тогда остаётся системный, приложение всё
  равно ходит по TCP; `PG*` из окружения оператора уводят `pg_ctl` и `psql` на **чужой** сервер,
  поэтому окружение кластера собирается с нуля; без внятной локали postmaster на macOS не
  стартует, а на минимальном Linux локалей может не быть вовсе — отсюда `--locale=C` и `LC_ALL=C`.
- **GStreamer из комплекта живёт своим окружением, и реестр плагинов — его главная часть.**
  По умолчанию реестр кешируется в `$HOME`, куда служба под systemd писать не может, поэтому он
  пересобирался бы при каждом старте — минуты на первом ролике с субтитрами. `GST_REGISTRY`
  уводит его в каталог установки, а проверку `dvbsubenc` мастер запускает в том же окружении,
  чтобы построить реестр один раз, на установке. Окружение считается дважды —
  `subtitles/gstreamer.ts` для службы и `scripts/bundle-gstreamer.mjs` для мастера, — потому что
  мастер работает до сборки; расхождение ловит тест в `scripts/bundle.test.mjs`.
- **Схема применяется SQL-файлами, а не `prisma migrate deploy`.** CLI со schema engine весит
  66 МБ и на целевой машине больше ни для чего не нужен. Запись в `_prisma_migrations` идёт в
  формате Prisma — иначе следующая `migrate deploy` на машине разработчика попыталась бы
  применить всё заново. Проверяется это не на глаз: после установки из комплекта
  `prisma migrate status` обязана отвечать «Database schema is up to date».

**Папка программы на рабочем столе**: `FluxIO Sessions/<имя> (<id>)`, создаётся при запуске
Electron (`apps/desktop/src/session-files.ts`). В неё автосохранение кладёт расписания Current и
Future, настройки кодирования и снимок сессии — то, чем станцию поднимают заново, когда базы уже
нет. База остаётся источником правды; кнопка «Восстановить сессию» в Control Center отдаёт
выбранный файл службе на проверку той же схемой и эфир не поднимает — момент старта выбирает
оператор. Закрытие окна программы при живом эфире спрашивает подтверждение, сохраняет сессию и
только потом останавливает линию; несохранённая сессия — повод спросить ещё раз, а не запрет
закрываться: из окна, которое не выпускает, оператор всё равно выйдет силой — вместе со службой.

**Новый нативный диалог**: канал в `apps/desktop/src/channels.ts` (и в союз `DesktopChannel`) →
та же строка в `preload.ts` с аннотацией `: DesktopChannel` → обработчик в подходящей группе
`apps/desktop/src/ipc.ts` → метод в `contextBridge` → тип в `apps/web/src/electron.d.ts`.
Сама работа с диалогом живёт в `apps/desktop/src/dialogs.ts`, проверка payload из renderer —
в `saveInput.ts`, создание окон и splash — в `windows.ts`.

Строки каналов **намеренно** продублированы в `channels.ts` и `preload.ts`: preload запускается
с `sandbox: true` и не может импортировать локальные модули в рантайме. Спасает `import type`
— он стирается при компиляции, а аннотация `: DesktopChannel` роняет сборку при расхождении.
Проверить, что в preload не появился рантайм-импорт: `grep require apps/desktop/dist/preload.js`
должен показывать только `electron`.

**Схема БД**: `apps/media-server/prisma/schema.prisma` → `npm run db:migrate:dev`.
`apps/media-server/src/generated/prisma/**` — сгенерированный клиент, руками не править.

## Соглашения

**Имена `GRUBER_*` — намеренное легаси.** Продукт переименован в FluxIO, но переменные окружения,
имя пакета `gruber-playout`, PostgreSQL database, service IDs и preload-мост `window.gruberDesktop`
сохранены ради обратной совместимости существующих установок. Не «чинить».

**Contracts-first.** Не описывай форму данных дважды. Тип на клиенте и на сервере должен выводиться
из одной Zod-схемы через `z.infer`.

**TypeScript строгий** (`tsconfig.base.json`): `strict`, `noUncheckedIndexedAccess`, `noUnusedLocals`,
`noUnusedParameters`. Неиспользуемый импорт ломает сборку.

**Тесты — node:test поверх скомпилированного вывода**, не ts-раннер: `tsc -p tsconfig.test.json`,
затем `node --test dist-test/*.js`. Юнит-тесты чистых функций, без моков процессов.

**Версия приложения** в runtime берётся из корневого `package.json`: так работают setup,
media-service, web-интерфейс и splash Electron. При выпуске синхронизируй версии корневого и
workspace `package.json` через npm-команду вместе с lockfile; не делай глобальную замену по
репозиторию. Правила нумерации и проверка выпуска — `docs/versioning.md`.

**Документация evergreen**: обновляй тематический файл в `docs/`, а историю этапов оставляй в Git.
Долгоживущие архитектурные решения оформляй ADR в `docs/adr/`. Документация на русском.

## Ловушки

- **Вырезая селектор из групповых правил CSS, легко унести тело правила.** `.a, .lottie-b { … }`
  при удалении второго селектора превращается в `.a,` перед следующим правилом — и `.a` молча
  получает чужие свойства или теряет свои. Так уже уехали панель ресурсов расписания и кнопки
  «Применить»: экран разъехался, а сборка и тесты остались зелёными. Проверять надо **свойства**
  каждого селектора, а не наличие селектора: сравнение списков селекторов эту потерю не видит.
- **Ожидание пути в тесте не пишется литералом.** `path.join` и `path.resolve` берут разделитель
  и букву диска у машины, на которой тест идёт: на Windows `/opt/x` превращается в
  `R:\opt\x`, а `join` даёт `\`. Литеральное ожидание проходит на macOS и падает на эфирной
  машине — причём падает на первом же `assert`, поэтому остальные проверки того же теста
  вообще не выполняются, и о них узнаёшь только со второго захода. Так уже ломались раздача
  интерфейса и окружение GStreamer. Сравнивай через тот же `path`, либо приводи разделители
  (`value.replaceAll("\\", "/")`) — тогда в тесте остаётся читаемый POSIX-литерал.
  Проверить на своей машине можно подменой `node:path` на `path.win32` крючком
  `module.register`: тесты без файловых операций прогоняются в чужой семантике как есть.
- **Путь Windows нельзя отдать наружу как есть — его съедают три разных разбора.** Все три
  сломали сборку комплекта на `R:\FluxIO-Bundle\…` и все три молчаливы:
  `tar` разбирает `R:\…` как «узел : путь» (наследие ленточных приводов) и уходит в сеть —
  `Cannot connect to R: resolve failed`; лечится не флагом `--force-local` (его знает GNU tar
  и не знает bsdtar из Windows 10+), а запуском `tar` в `cwd` каталога-родителя с
  относительными именами. **PostgreSQL** внутри одинарных кавычек `postgresql.conf` разбирает
  `\` как escape: `…\release\…` приезжает как `…elease…` (`\r` — возврат каретки), postmaster
  не стартует, в логе «could not open log file» с огрызком вместо пути — пути в конфиг пишутся
  прямыми слэшами (`configPath` в `bundle-postgres.mjs`). **Node** с 18.20.2 отказывается
  запускать `.cmd` без `shell: true` (CVE-2024-27980): процесс не стартует, `status` остаётся
  `null`, и `status ?? "unknown"` сообщает «завершился с кодом unknown» вместо причины —
  зови npm через `buildNpmInvocation` из `scripts/npm-invocation.mjs` (общий для мастера и
  сборщика) и показывай `result.error` через `describeProcessFailure`.
- **Новый тест в `apps/web` регистрируется вручную в двух файлах.** `apps/web/tsconfig.test.json`
  перечисляет `include` пофайлово (нужен и сам модуль, и его `*.test.ts`), а `apps/web/package.json`
  перечисляет пути `dist-test/...` в скрипте `test`. Забудешь первое — файл не скомпилируется;
  забудешь второе — `node --test` молча не запустит его. В обоих случаях сборка зелёная.
  В этом сборочном контуре (`NodeNext`) относительные импорты обязаны быть с расширением `.js`,
  хотя Vite принимает и без него.
- **Число строк расписания ничем не ограничено, кроме тела запроса.** Потолок в тысячу
  элементов у `playlist`, `currentPlaylist` и `futurePlaylist` отвергал недельную сетку целиком:
  168 часов из отбивок и анонсов — это больше тысячи строк, а снимок проверяется одной схемой,
  и оператор видел «сессия не сохраняется» сразу после импорта расписания, без всякой связи с
  ним. Размер держит `largePlaylistBodyLimitBytes` (64 МБ) — единственный потолок, который не
  врёт: ролик в снимке весит около 2,4 КБ и лежит там дважды (медиатека плюс расписание).
  Выше поднимать не надо: разбор JSON синхронный, и на 20 000 строк служба уже не отвечает
  на эфирные маршруты 0,6 с — это видно в журнале строкой `SERVICE`.
- **Сохранение сессии — всё или ничего, и отказ молчалив.** Снимок проверяется одной схемой:
  превышение любого `max` отвергает его целиком, автосохранение перестаёт проходить, и после
  перезапуска возвращается **предыдущий удачный** снимок — оператор видит это как «пропали пути
  к AGE, переводам и логотипу», хотя пропало всё, что он сделал с того момента. Поэтому потолки
  списков путей щедрые (размер держит лимит тела запроса), причина отказа пишется в журнал
  строкой `SESSION` (`describeValidationError` — поле и претензия, а не весь разбор Zod), а
  сообщение в интерфейсе говорит о последствии, а не только об ошибке.
- **Опознаватель показа сцены ограничен 64 символами, и это ломает сохранение целиком.**
  `playoutSceneShowSchema.id` — единственный `max` среди опознавателей модели, а снимок
  сессии проверяется одной схемой: один переросший идентификатор отменяет **всё**
  сохранение. Так и вышло с импортом расписания: `schedule-scene-<индекс>-<id эффекта>`
  при `fx2-<вид>-<uuid>` даёт 77 знаков, и оператор видел «сессия не сохраняется» без
  всякой связи с импортом, который её и сломал. Склеивай такие опознаватели только через
  `sceneShowId` из `apps/web/src/schedule-ids.ts` (+ тест), а состояния прежних версий
  чинит `withValidSceneShowIds` на сохранении — переимпортировать расписание ради этого
  оператор не должен.
- **Разбор Zod в ответ маршрута не уходит.** `badRequest` и `playoutErrorReply` отдают
  `describeValidationError` — поле и претензию. Полный дамп оператор видел как простыню из
  сотни одинаковых записей, в которой не найти, что именно сломалось.
- **Поле, не объявленное в `workspaceSessionAssetSchema`, теряется при сохранении сессии.**
  Zod по умолчанию выбрасывает незнакомые ключи, а сессия сохраняется автоматически, поэтому
  промах виден не сразу: оператор раскладывает плашки по расписанию, автосохранение молча
  срезает их, и после перезапуска расписание чистое. Так уже пропадали `scenes` и `audioTracks`.
  Добавил поле в `MediaAsset` — добавь его **и** в схему сессии, и в `playoutItemSchema`.
  То же и с состоянием станции: путь к папке переводов лежит в настройках, а найденные в ней
  языки — в `workspaceAudioTrackLibrarySchema`. Пересканировать папку при восстановлении нечем
  (это ffprobe по каждому файлу расписания), поэтому без сохранённого списка оператор после
  перезапуска видел выбранную папку и пустой набор дорожек.
- **`@gruber/scene-renderer` потребляется как скомпилированный `dist`, как и contracts.**
  Правка `drawScene` без сборки не доходит ни до редактора, ни до эфира — а сборка и тесты
  остаются зелёными, потому что тесты пакета идут по своему `dist-test`. Ради этого в корне
  есть `build:renderer` (contracts + renderer), и на него завязаны `build`, `typecheck`,
  `dev:web` и `dev:server`. Не откатывай их на `build:contracts`.
- **Сгенерированный Prisma-клиент одновременно в `.gitignore` и в индексе git** (15 файлов
  закоммичены до появления правила). `npm run db:generate` даёт diff-шум в файлах, которые правилом
  считаются игнорируемыми. Либо `git rm --cached` их, либо убрать правило — сейчас состояние
  противоречиво.
- **Номер 6.0.23 пропущен.** Коммит `3e8d7df` назван 6.0.23, но строки версии тогда не подняли;
  в v6.0.24 дерево синхронизировано целиком, минуя 6.0.23. Не пытайся «восстановить» пропуск.
- **Цепочка TSDuck для DVB-субтитров чувствительна к двум вещам** (обе стоили целого
  расследования, см. `buildTsdDuckCommand`): `-P merge` обязан идти **до** обеих стадий `-P pmt`
  — PID, уже объявленный в PMT основного потока, merge считает конфликтующим и молча
  выбрасывает, причём `--ignore-conflicts` не помогает. И `--max-queue` должен быть небольшим
  (сейчас 256): merge начинает вставку только после наполнения очереди, а subtitle PID отдаёт
  ~60 kbps, поэтому 4096 пакетов копятся полторы минуты и короткий ролик заканчивается раньше.
- **Рендерер аудиодорожки обязан отдать ровно `durationSeconds` ролика.** Program encoder читает
  видео со stdin и по одному raw-PCM pipe на дорожку; мультиплексор чередует все элементарные
  потоки, поэтому один молчащий вход останавливает выдачу целиком, а не только свою дорожку.
  Длину закрепляет хвост `apad=whole_len=N,atrim=end_sample=N` в
  `buildFfmpegClipAudioProducerCommand` (короткое добивается тишиной, длинное режется по сэмплу),
  а `#padClipAudio` в supervisor страхует это на уровне байт. Любой новый фильтр в этой цепочке
  ставь **до** хвоста — `loudnorm` и `aresample` меняют число сэмплов.
- **У каждого конца трубы обязан быть обработчик `error`.** `pipe()` вешает на приёмник свой, но,
  не найдя рядом ни одного пользовательского, **переизлучает** ошибку обратно — а необработанное
  событие `error` на потоке выносит весь процесс. Так служба и падала на смене ролика: рендерер
  уходит на EOF ролика, а рисовальщик сцены (плашка «Смотрите далее» рисуется как раз в конце)
  дописывает последний кадр в уже закрытую трубу. Снаружи это выглядело как обрыв эфира целиком,
  причём в журнале не оставалось ни строки. Разбор кодов и обёртки — `ffmpeg/pipe-errors.ts`;
  `installBrokenPipeGuard` в `index.ts` — последняя страховка, а не замена обработчикам.
  И отдельно: рисовальщик закрытия не видит — он пишет в службу, а закрывается труба дальше по
  цепочке, — поэтому на ошибке трубы его надо гасить, иначе он рисует в пустоту до конца сессии.
- **DVB subtitle PID и SCTE-35 cue plan фиксируются на старте транспортной сессии.** Их изменение
  требует Stop/Start; AGE / LOGO / FX / burn-in SRT будущих роликов, наоборот, применяются на лету
  через `PUT /api/playout/playlist`. Не перепутай эти два класса изменений.
- **Stinger нельзя положить одним оверлеем поверх стыка.** Эфир катится независимыми
  рендерерами — по процессу на ролик, — поэтому стык проходит по границе двух процессов.
  Переход режется по `Cut point`: кадры `[0, cut)` ложатся на хвост ролика A, кадры
  `[cut, duration)` — на голову ролика B из того же файла через `sourceInSeconds` у FX-слоя.
  Расписание, PCR и SCTE-35 при этом не меняются. Обе величины округляются до кадровой сетки —
  разность двух округлённых значений тоже (иначе вылезает `0.6799999999999999`).
- **PTS свёрнут, а программное время — нет.** Поле PTS 33-битное на 90 кГц: оно переполняется
  каждые ~26.5 часа, а недельное расписание длиннее втрое. Поэтому ожидаемое время реплики
  (`опора видео + смещение реплики на программной шкале`) сравнивается с настоящим PTS **по
  модулю периода**, а не одной поправкой: расходятся они на несколько периодов сразу, и одна
  поправка оставляла от разницы ровно период — «DVB subtitle clock mismatch … -95443717 ms»
  при часах, сбитых на миллисекунду. По той же причине опора видео-часов не переезжает на
  значение, которое **намного** меньше её (`resolveVideoPtsOrigin`): ниже опоры на секунды —
  это переупорядочивание кадров, ниже на часы — переполнение счётчика.
- **Экранные часы обязаны идти по эфирному времени, а не по `%{localtime}`.** Рендерер
  следующего ролика запускается заранее, поэтому системные часы нарисовали бы в первых кадрах
  будущее. Supervisor держит `#airEpochAnchor` (момент реального выхода ролика) и передаёт
  `airEpochSeconds`; надпись строится как `%{pts:gmtime:<эпоха>:%H}`. `gmtime` со сдвигом пояса,
  а не `localtime` — чтобы результат не зависел от TZ сервера.
- **Звук эффекта подмешивается строго между `loudnorm` и хвостом длины.** `amix` идёт с
  `normalize=0` (не приглушать основную дорожку) и `duration=first` (не удлинять её), а
  `apad=whole_len/atrim=end_sample` остаётся последним. Файл вставки без звуковой дорожки
  `prepareItems` молча выбрасывает: отставший аудиовход останавливает мультиплексор целиком.
- **Расписание хранит абсолютные пути, а не файлы.** После перезапуска или переноса проекта
  графика может исчезнуть, и раньше это всплывало отказом на Start. Проверка —
  `POST /api/effects/verify` плюс `apps/web/src/missing-graphics.ts`; диалог замены вызывается
  после восстановления сессии и после импорта расписания. Новый маршрут значит, что
  media-service после обновления нужно перезапустить, иначе проверка получает 404.
- **Опрос статуса идёт раз в секунду ВСЕГДА, а не только во время эфира**, и перерисовывает
  всё дерево приложения. Любой массив или
  функция, собранные прямо в JSX `App.tsx`, меняют идентичность на каждом опросе и тянут за
  собой перерисовку тяжёлых экранов — у оператора «залипают» селекторы и поля ввода.
  `EffectsScreen` обёрнут в `memo`, а его обработчики проходят через `useStableCallback`
  (`apps/web/src/stable-callback.ts`). Новый проп к нему обязан быть стабильным, иначе memo
  молча перестаёт работать: проверяется счётчиком рендеров в консоли, а не на глаз.
  Узлу, которому нужен **живой** статус, его берут из контекста `usePlayoutStatus` внутри
  самого узла — так сделаны эфирный монитор плейлиста и строка «что играет». Пропсом статус
  снял бы memo со всего экрана вместе со списком роликов.
- **Не задавай высоту прокручиваемой панели расчётом от `100vh`.** У панели настроек эффекта
  было `max-height: calc(100vh - 190px)`; над ней появились новые блоки, и нижний край ушёл
  за границу области прокрутки — элементы в этой полосе перестали принимать клики, а снаружи
  это выглядело как «залипший» селектор. Экран не прокручивается сам: прокручиваются колонки,
  высоту задаёт раскладка.
- **`input[type=number]` отдаёт пустую строку для незавершённого ввода** — «1.», «-», «1e».
  Прямое `Number(value)` даёт ноль и возвращает поле назад: набрать дробное значение
  невозможно. Держи локальный черновик строки и отдавай наружу только законченные числа.
- **Правка настроек не должна идти в глобальное состояние на каждое нажатие клавиши.**
  Перерисовка всего дерева (в инспекторе эффектов — селектор на 347 шрифтов) ощущается как
  залипание ввода. Локальный черновик плюс задержка ~300 мс перед записью в библиотеку.
- **Старый media-service молча срезает новые поля.** Zod по умолчанию выбрасывает незнакомые
  ключи, поэтому служба предыдущей версии теряет `broadcast` при сохранении сессии, а эффекты
  второго уровня превращаются в пустые записи. Интерфейс сверяет `health.version` с
  `applicationVersion` и предупреждает; после правки контрактов службу надо перезапускать.
- **`input[type=color]` возвращает значение строчными буквами.** Приведение к верхнему регистру
  расходится с DOM, React возвращает поле назад, и пипетка перестаёт слушаться. Регистр не
  трогай ни на входе, ни на выходе.
- **Строки таблицы `name` шрифта — UTF-16 big-endian.** Порядок надо менять у байтов и до
  декодирования (`Buffer.swap16()`); перестановка готовых символов после `toString("utf16le")`
  даёт иероглифы вместо имён. Там же: у семейства выбирается начертание с наименьшим числом
  стилевых слов в имени файла, иначе «Arial» ведёт на `Arial Bold Italic.ttf`.
- **Нулевой `durationSeconds` значит «файл не разобран», а не «ролик пустой».** У ролика из
  импортированного расписания длительность известна только из `declaredDurationSeconds`, и
  прямой `Math.min(declared, source)` давал ноль: всё, что отсчитывается от конца ролика
  (плашка «Смотрите далее», выходная анимация, стингер), уезжало в самое начало. Считай
  длительность через `airDurationSeconds` из `apps/web/src/clip-duration.ts`.
- **Бегущая строка обязана обрезаться по своей области.** Иначе она уезжает за плашку, и
  снаружи это выглядит как «текст не подставился». `drawText` в `packages/scene-renderer`
  ставит `clip()` по прямоугольнику узла; период круга — `(ширина области + ширина строки) /
  скорость`, поэтому длинный и короткий текст едут одинаково.
- **Плашка меряется по образцу, а не по текущему значению.** У часов оно меняется каждую
  секунду, и привязанная подложка дёргалась бы вместе с цифрами. Образец задаёт `fitSample`
  в описании поля сцены.
- **Ключ текстового поля руками не набирают.** Промах не виден: плашка молча выходит в эфир
  с шаблонным текстом. Поля объявляет сама сцена (`template.fields`), и в интерфейсе они
  выбираются списком.
- **Консоль Windows умеет останавливать службу целиком.** Запись в stdout там синхронна (на macOS —
  асинхронна, это задокументированная разница Node), а `launch.mjs` поднимает media-service с
  `stdio: "inherit"`. Щелчок внутри консольного окна включает выделение QuickEdit, вывод замирает —
  и однопоточная служба встаёт на первом же `console.info`, вместе с ней перестают отвечать
  `/api/playout/status` и весь интерфейс. Поэтому событие, которое случается несколько раз в
  секунду (наблюдение DVB-пакета), помечается `quiet` и в консоль не идёт; в журнале и в статусе
  оно остаётся. Флаг ставит supervisor: разбирать текст событий снаружи нельзя.
- **Список системных шрифтов кешируется на всё время работы службы** (`SystemFontsService`).
  Разбор читает каждый файл шрифта целиком, а в `C:\Windows\Fonts` их сотни, включая коллекции
  CJK по десятку мегабайт, и каждое чтение проходит через антивирус: на macOS это 0.9 с, на
  эфирной машине — секунды, и всё это время служба не отвечает на эфирные маршруты. Шрифт,
  установленный на ходу, появится после перезапуска службы — так же, как возможности FFmpeg.
- **Сон машины неотличим от заминки по одним часам.** Таймер `watchEventLoop` не тикает ни когда
  служба стоит на длинной синхронной работе, ни когда спит ноутбук, — и закрытый на ночь мак писал
  в журнал «сервис не отвечал 900 с». Отличает их процессорное время: занятая служба его тратит,
  спящая — нет. Порог мягкий (ждать диска — тоже заминка, а процессор при этом простаивает),
  поэтому одного его мало и нужен потолок в `sleepMs`.
- **Ожидаемая жалоба при остановке ошибкой не пишется.** Уровень записи эфирного события берётся
  из текста (`playoutEventLevel`), потому что supervisor отдаёт строку, а не код. Исключение
  объявляет он же, флагом `expected`: выдача закрывается после того, как эфир кончился, и TSDuck
  успевает пожаловаться на сокет, которого уже нет. Красная строка на штатном завершении приучает
  не читать журнал там, где ошибка настоящая.
- **Эфир делит машину со всем остальным, и диск ему никто не уступит сам.** На эфирном сервере
  копировали файлы на тот же диск, с которого идёт вещание: диск стоял на 100 % при 40 МБ/с, а
  рендерер читает ролик по мере надобности, выдача идёт в реальном времени — и затык диска
  становился стоп-кадром. Приоритет диска выше «нормального» обычная программа в Windows поднять
  не может, поэтому `ffmpeg/air-resources.ts` делает две доступные вещи. Процессы эфира и сама
  служба получают высокий приоритет (`HIGH_PRIORITY_CLASS`, **не** REALTIME — тот ставит машину
  колом), предпросмотр — нет: он не вправе отбирать процессор у выдачи. И ролик дочитывается в
  кэш системы, когда запускается его рендерер (первый на старте и предзапущенный следующий), —
  по одному, с того байта, откуда ролик войдёт в эфир, не больше половины свободной памяти и
  2 ГиБ; обрывается вместе с рендерерами и не бросает исключений. Копировщику на той же машине
  нужен фоновый режим (`PROCESS_MODE_BACKGROUND_BEGIN`) — только он опускает чужой приоритет
  диска. На Unix отрицательный nice требует прав: без них отказ называется одной строкой, а эфир
  идёт как шёл.
- **Долгая синхронная работа в media-service выглядит как залипший интерфейс.** Сервис
  однопоточный: пока идёт разбор большого расписания, не отвечает ни один
  маршрут. Уступай цикл событий по времени (не дольше ~16 мс подряд), а не по числу итераций —
  длительность итерации зависит от данных. Заминки дольше 500 мс пишет `watchEventLoop`
  в суточный журнал.
- **Шрифт задаётся файлом, а не именем семейства.** Шрифт без кириллицы отдаёт в эфир пустые
  прямоугольники, и заметно это только на выходе. Список системных шрифтов с разбором таблицы
  `cmap` — `apps/media-server/src/effects/system-fonts.ts`; интерфейс делит его на группы
  с кириллицей и без, а планировщик предупреждает при кириллице без выбранного шрифта.
- **Логотип наложен с `shortest=1`, поэтому его вход обязан быть длиннее ролика.**
  Анимированный логотип (mov/webm/gif) с повтором держится
  входом (`-stream_loop -1`, у gif — `-ignore_loop 0`), однократный — последним
  кадром (`tpad=stop=-1:stop_mode=clone`). Просто «дать анимации закончиться»
  нельзя: закончившийся вход обрежет по себе весь эфир.
- **Падение транспортной стадии обязано называть причину.** Код выхода сам по себе не говорит
  ничего: «TSDuck SRT relay exited with 1» отправлял оператора в журнал за строкой, которая
  уже была прочитана. `describeTsdDuckExit` кладёт в статус последнюю ошибку TSDuck, а у
  SRT — ещё и то, что проверять: у caller это «приёмник не ответил, смотрите порт, firewall,
  passphrase и stream id», у listener — «к нам никто не подключился». Восстанавливать связь
  самому нельзя: FFmpeg пишет в трубу tsp, и перезапуск транспорта означает перезапуск всей
  цепочки, то есть эфира.
- **Одновременно разрешена одна эфирная сессия**; повторный Start отдаёт `PlayoutConflictError`.
- **`GRUBER_SECRET_KEY` обязателен** для сохранения SRT/RTMP секретов (AES-256-GCM в
  `DatabaseService`). Без него сохранение конфигурации с секретом падает.
- **media-service читает `.env` по относительному пути** `../../../.env` от собственного модуля
  (`apps/media-server/src/index.ts`), то есть от корня репозитория. Изменение раскладки сборки
  ломает загрузку конфигурации.
- **Крупные файлы, где легко потеряться**: `apps/web/src/App.tsx` (~2400 строк, всё состояние
  приложения), `apps/media-server/src/ffmpeg/playout-supervisor.ts` (~2300),
  `apps/media-server/src/app.test.ts` (~2800).
- **Возрастная маркировка без картинки требует FFmpeg с libfreetype.** Это единственное, что
  ещё рисуется фильтром `drawtext`: плашки, бегущую строку, часы и отсчёт рисует сцена своим
  растеризатором. Ловится в `capabilities.supports.dynamicText`, preflight объясняет причину.
  И отдельно: в `drawtext` двоеточие обязано быть экранировано `\:` **даже внутри одинарных
  кавычек** — кавычки снимает разбор графа, а деление на опции идёт уже после. Запятые кавычки
  защищают, двоеточия — нет.
- **Burn-in субтитры требуют FFmpeg с libass.** Обычная Homebrew-формула `ffmpeg` собрана без
  него, фильтра `subtitles` нет, и любой граф с burn-in падает как `AVFilterGraph: No such filter`.
  Это ловится в `capabilities.supports.burnInSubtitles`, preflight и превью отдают внятный текст.
  Лечится `brew install ffmpeg-full` либо переключением Subtitle output в DVB.
- **Превью считаются пулом на 4 задачи** (`thumbnailConcurrency` в `ffmpeg/media-preview.ts`).
  Раньше была одна общая очередь, и последняя картинка ждала все предыдущие — при импорте
  сотен файлов превью просто не догружались. Фильтр `thumbnail=n=8` вместо дефолтных 100 кадров:
  на 4K ProRes это 0.14 с против 0.64 с.
- **Граф фильтров из файла читается через `-/filter_complex`, а не `-filter_complex_script`.**
  Старое имя опции FFmpeg 9 уже не знает (`Unrecognized option`), новое — общий приём
  `-/<опция> <файл>` из FFmpeg 7. Путь этот нужен там, где граф не влезает в командную строку,
  и в бою пока не включается; проверяют его интеграционные тесты под
  `GRUBER_RUN_FFMPEG_TESTS` / `GRUBER_RUN_SCTE35_TESTS` — в обычный `npm test` они не входят,
  но на FFmpeg 9.0.1 оба проходят. Понадобится FFmpeg старше 7 — выбор имени опции придётся
  делать по версии из `capabilities`.
- **`npm ci` сносит `node_modules`, а Windows не отдаёт занятые `.node`.** Установка поверх
  работающего FluxIO обрывалась на `EPERM: unlink` у `skia.win32-x64-msvc.node`, уже снеся
  половину дерева, и дамп npm ничего не говорил о настоящей причине. `findLockedNativeFiles`
  проверяет занятость переименованием **до** установки (открыть на чтение Windows даёт и
  занятому файлу), а `describeLockedNativeFiles` называет файлы и команду остановки. Гасить
  процессы сам мастер не имеет права: на эфирной машине это разрыв выдачи ради установки
  зависимостей — решение остаётся за оператором.
- **Заголовок JSON уходит только вместе с телом.** `api()` в `apps/desktop/src/session-files.ts`
  ставил `content-type: application/json` на каждый запрос, а остановка эфира идёт `POST` без тела:
  Fastify отвечает на такое `400 FST_ERR_CTP_EMPTY_JSON_BODY`, и закрытие окна при живом эфире
  **не проходило никогда** — оно отменялось окном «Закрытие отменено». Проверяется одним `curl` с
  этим заголовком и пустым телом; в интерфейсе `media-api.ts` той же ошибки нет, потому что свои
  запросы без тела он шлёт без заголовка.
- **`spliceinject --wait-first-batch` останавливает весь транспорт.** tsp — одна цепочка: флаг держит
  её, пока файл меток не загрузится, а файл, который не загрузился (нет на диске, путь не открылся,
  разбор отверг значение), держит её вечно и молча — выдача и зеркало предпросмотра стоят, а FFmpeg
  продолжает рапортовать кадры. Снаружи это выглядело как «с метками SCTE не работает предпросмотр».
  Проверено на tsp: отсутствующий и отвергнутый файл с флагом — 0 байт на выходе, и `SIGTERM` процесс
  не останавливает; без флага поток идёт, а отказ уходит в журнал. Поэтому флага нет, файл читается
  первым же опросом (`--poll-interval 100 --min-stable-delay 0`), а пропуск ловит `missedScte35Cue`:
  метка, не замеченная splicemonitor к своему моменту, переводит SCTE-35 в `failed`. Файлы для
  TSDuck передаются **именем**, а сам он запускается в их каталоге (`#spawnTsdDuck`): каталог лежит
  в профиле пользователя и может содержать кириллицу, которую нативному tsp разбирать незачем.
- **Строка расписания собирается, только подойдя к области просмотра** (`DeferredEntry` в
  `PlaylistPreviewScreen.tsx`). Неделя — это 1196 строк по ~72 узла: вход на вкладку собирал
  86 тысяч узлов (0,6–1 с на быстром Mac) и разом запрашивал миниатюры всех роликов. Служба режет
  их FFmpeg по четыре, браузер держит на картинках все шесть соединений к хосту, и опрос статуса
  стоял за ними в очереди до 1,2 с: через 10 секунд после импорта было загружено 396 миниатюр из
  1196. Заглушка несёт тот же `data-asset-id`, поэтому прокрутка к ролику в эфире её находит, а её
  высоту задаёт `deferredEntryHeight` — поменял высоту строки в CSS, поправь и её.
- **Правка, которая трогает все ролики, обязана уходить в эфир одним шагом.** Логотип лежит на
  каждой строке, и ползунок, пишущий на каждом шаге, запускал горячую замену недели на каждый
  процент: служба готовила ролики поштучно, а журнал заваливало «1/1 clip(s) checked». Ползунки
  логотипа отдают значение по отпусканию (`CommitRange`), `updatePlaylist` готовит изменённые
  ролики одной пачкой и пишет одну строку итога, а тайм-аут `PUT /api/playout/playlist` — как у
  старта: замену, оборванную клиентом, служба всё равно доводит.
- **Удаление программы не имеет права застревать на том, чего уже нет.** Снятие службы шло
  `Unregister-ScheduledTask` без проверки, и на несуществующей задаче PowerShell отвечал
  `ObjectNotFound`: мастер падал **до** удаления базы, файла окружения и записи в реестре, а
  `Stop-ScheduledTask` перед ним успевал отработать — снаружи это выглядело как «программа ушла
  в offline, но не удаляется», причём навсегда: второй заход упирался в то же место. Служба
  снимается через `platformServiceRemoveCommand` (задача снимается, только если она есть; у
  systemd — только если есть файл юнита), отсутствующий `.env` больше не читается, а неудача с
  базой не отменяет удаления — она уходит предупреждением с именем и причиной. Настоящий отказ
  снятия (нет прав) по-прежнему роняет команду: оставленная работать служба держит порт.
- **`gst-inspect-1.0` при первом запуске строит реестр плагинов несколько минут.** `setup.mjs`
  это учитывает (таймаут 300 с, повтор, флаг `--skip-gstreamer-check`); любой новый код, дёргающий
  gst-инструменты, должен закладываться на то же самое.
